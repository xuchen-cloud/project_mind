# Project File preview / #124 WP4

Actual DSH TextBody, CodeBody (Shiki), MarkdownBody, ImageBody, PdfBody, HtmlBody/BasicHtmlFrame and ZoomViewport/ZoomControls from `dsh-v0.2.0-rc.2`, commit `639ed015397290b3745d163aafe02ffee4aa3f84`. Selected source files are retained under `upstream/client/ui-sidebar-documentpreview`, with original and patched SHA-256 in `../provenance.json`; original MIT and third-party notices remain included. The adapter creates no Session or model runtime. File identity and layout belong to the main application.

`ProjectFileContent` resolves latest through the native binding before reading an immutable version/hash. Fixed history reads snapshots without requiring a ready live file. Text/Markdown/HTML source pagination stays on the same version/hash. `onSourceReady` reports only the verified loaded bytes' fixed SourceRef; beginning another read, hiding or unmounting clears it. `initialView` restores scroll/zoom when the main shell remounts the selected File/version, including a one-time late arrival after sourceReady identifies the actual version; later saved-view props do not pull back user scrolling. PDF page locations wait for first/target page layout; saved scroll restores its within-page offset. Late responses cannot render or publish sources after abort. Original ImageBody revokes blob URLs and original PDF sessions dispose workers; the host removes its observers and themed portal on unmount.

Current relative Markdown images (inline and reference syntax) and static HTML image/stylesheet resources use bound native `resolveRelated` followed by `readBytes` of its actual same-Project File/hash. Remote references are not fetched. The original Markdown source is preserved. Historical related snapshots are unavailable and explicitly reported, rather than loading current dependencies. Static HTML uses unchanged pinned DSH sanitization/CSP and `sandbox=""`; the interactive preference is permanently false. HTML source uses the same verified fixed text in DSH TextBody, with exact line targeting and no second source-read UI. The unused legacy FileHtmlPreview was removed; ProjectFileContent owns the current entry point. Scripts/navigation/forms remain disabled. Nested CSS URLs/imports and HTML srcset are unsupported and stated. Office preview/editing is not claimed.

Visited static HTML stays mounted while hidden, preserving its original opaque iframe/browsing context. All async reads abort and sourceReady clears; other document bodies still unmount. When visible again, bound revalidation and resource reads compare the actual prepared display bytes as well as root version/hash. Identical output reuses bytes/renderer identity without assigning srcDoc again; version/content/resource changes or failures retire the old frame. Closing/reopening, mode switches or restarting cannot restore iframe-internal position. `initialSourceMode` and `onViewChange({sourceMode})` bind HTML/Markdown source mode to the shell store without another read path. DOM lifecycle tests cover this behavior; platform WebView scroll acceptance remains with the main agent.

PDF policy: original DSH requests PDF.js 6.3.289; the host reuses its existing locked **6.2.108**, validated with actual two-page text/color rendering, BinaryDataFactory and worker lifecycle tests. Worker/font/cmap/wasm bytes all come from that same version. `generate-pdf-assets.mjs` creates a build-imported asset map and per-input SHA-256 inventory. `licenses/` retains PDF.js Apache-2.0, cmap, Foxit/Liberation font, JPEG2000/JBIG2/QCMS notices. DOMPurify **3.4.11**, required by pinned HTML source, is the only added root dependency; its dual-license notice is included. Assets do not require preview-time downloads.

Verification and contracts: [HANDOVER.md](HANDOVER.md). No GUI, platform acceptance, #115 interactive isolation or whole-Issue completion is claimed.
