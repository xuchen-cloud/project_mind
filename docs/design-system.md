# Project Mind Alpha Design System

状态：当前正式基线  
更新时间：2026-09-28

## 1. 目的与边界

这是一套服务于当前代码实现的轻量设计系统。

它的职责是：

- 记录已经落在代码中的视觉基础与交互规则
- 统一当前工作区产品的语义
- 帮助后续实现维持一致

它当前不承担：

- 多主题系统
- 完整 token 平台
- 面向营销站点的品牌规范
- 为历史遗留页面继续扩充旧组件族

当前实现基线主要对应：

- [src/styles/app.css](../src/styles/app.css)
- [src/ui/components](../src/ui/components)
- [src/components/layout](../src/components/layout)
- [src/components/workspace](../src/components/workspace)
- [src/components/project](../src/components/project)
- [scripts/check-ui-standards.mjs](../scripts/check-ui-standards.mjs)

## 2. 设计方向

当前界面应保持以下气质：

- 稳定
- 克制
- 可信
- 适合长时间工作的编辑型工作台

它不是：

- 通用 SaaS 仪表盘
- 娱乐化效率工具
- 强装饰的 AI 产品壳

持续有效的方法论：

- `state before detail`
- `fast capture, deliberate structure`
- `layered information`
- `calm density`
- `local confidence`

## 3. 表达规则

### 3.1 先减法，再布局

默认先问：

- 这段信息是否真的需要出现
- 一个信号能否讲清楚
- 是否能用一行完成表达

具体规则：

- 能用文本解决的，不强行卡片化
- 能用 badge 解决的，不强行字段化
- 只读信息不伪装成输入框
- 不为“看起来完整”补无效说明

### 3.2 主编辑面优先

当前产品是编辑型工作台，所以主视觉资源要优先给：

- Workspace主区
- QuickNote
- Record正文

而不是优先给：

- 装饰性卡片
- 过度边框
- 多余浮层

### 3.3 长驻工具侧区

侧边栏和 Todo Rail 是长期驻留工具，不应看起来像临时插入物。

因此：

- 背景层级要弱于主编辑区
- 交互要直接
- 信息要紧凑但不压迫

## 4. Foundations

### 4.1 色彩

当前核心色彩语义：

- 暖白主背景
- 轻微分层的浅灰背景
- 克制的蓝绿色强调
- 明确但不刺眼的危险色

正文颜色必须使用可读的语义层级：

- `text-primary`：正文、标题与主要操作
- `text-secondary`：辅助说明与元数据，仍需满足正常阅读
- `text-tertiary`：眉题、路径等低优先级信息，不用于关键操作
- `text-disabled`：仅用于不可操作状态

旧的 `text-muted` 与 `text-soft` 只作为兼容别名，分别映射到 `text-secondary` 与 `text-tertiary`。

设计意图：

- 主区适合长文阅读与编辑
- 侧区与轻浮层通过背景层级区分，而非强阴影堆砌
- 强调色只用于选中、激活、关键 CTA 与轻量焦点反馈

### 4.2 字体

当前字体方向是“编辑型工作台”，而非通用系统默认感。

项目中使用的关键字体资源包括：

- `Work Sans`
- `Noto Sans SC`
- 预留的衬线正文方案

要求：

- UI 文本保持清晰、紧凑
- 长正文阅读不应显得机械或拥堵

### 4.3 文字层级

当前文本层级重点是：

- `caption`
- `ui`
- `body`
- `title`
- `headline`
- `display`

使用原则：

- `body` 是主工作面默认层级
- `ui` 用于控件和轻说明
- `caption` 只用于弱标签、统计与眉题

### 4.4 圆角与阴影

当前整体偏克制：

- 小组件使用 6px 到 8px 圆角
- 模态与较大浮层使用更高圆角
- 阴影只在浮层与对话框中明显出现
- 长驻侧栏和 Todo Rail 使用纯色背景与分隔线，不使用装饰性渐变、模糊或悬浮阴影；滚动边缘的功能性渐变遮罩必须遵循下述滚动规范

### 4.5 动效

新增或调整的交互动效只使用三档，并通过语义 token 引用：

- `100ms`：按压反馈
- `160ms`：颜色与常规控件状态
- `220ms`：偶发的浮层或较大状态变化

CSS 分别使用 `--duration-fast`、`--duration-standard`、`--duration-deliberate`；JS 时序使用同名语义常量。`1ms` 只作为 reduced-motion 下关闭位移的技术值，不属于视觉时长档位。

共享 `Button`、`IconButton` 与 `ToolbarButton` 在指针按下时使用 `scale(0.97)`；reduced-motion 下取消位移。持续 loading spinner 使用线性旋转，并在 reduced-motion 下停止旋转。

默认界面不添加动效。浮层与位移动效必须显式 opt-in，只允许 `transform`、`opacity`，单次揭示可使用 `clip-path`；禁止动画布局属性。键盘高频路径保持即时。凡使用 translate、scale 或 rotate，都必须提供 `prefers-reduced-motion` 或 `motion-reduce` 降级；持续 spinner 是唯一允许的长时线性动画，并在 reduced motion 下停止。

## 5. 当前界面骨架

### 5.1 Workspace Gate

应像正式起始页，而不是占位对话框。

要求：

- 有明确的主次操作
- 有最近工作区回流
- 有稳定、可信的第一印象

### 5.2 Top Bar 与页签

顶栏是工作区级控制带。

要求：

- 轻量
- 紧凑
- 持续可扫读
- 不把项目标签做成笨重导航条
- Workspace 是固定在最前、不可关闭的图标页签
- Project 页签使用浏览器式圆角轮廓；选中、未选中和悬浮态保持文字、图标与关闭按钮在同一水平线
- 页签切换以共享指示层平移和缩放，不重新播放整块进入动画

### 5.3 主区

主区视觉优先级最高。

要求：

- 足够宽
- 滚动清晰
- 封面、标题、QuickNote 与 Record 位于同一滚动面并保持稳定节奏

### 5.4 Sidebars 与 Rails

当前有三类长期侧区：

- 工作区侧边栏
- 项目侧边栏
- Todo Rail

共同规则：

- 背景弱于主区
- 搜索与切换动作靠前
- 列表项 hover 和 active 状态需要清楚但克制

### 5.5 右侧栏显示模式

- Workspace、Project 首页和内容页共用右侧栏，内容范围跟随当前 Workspace / Project。
- 默认以悬浮模式打开，覆盖在内容右上方，不压缩正文；点击页面其他内容或键盘焦点移出后自动收起。面板内的菜单与 Portal 浮层属于同一交互区域。
- 固定后占用右侧布局空间，点击外部不收起；可手动收起或取消固定。悬浮 / 固定偏好与宽度一同保存，跨页面和重新启动后沿用。
- 显示 / 隐藏入口统一放在上层工具栏；右栏内部不重复提供收起按钮，只保留固定 / 悬浮切换及待办操作。
- 收起时保留待办草稿，沿用待办现有的点击外部提交行为；隐藏内容退出键盘导航，也不响应正文的点击与 Escape。Escape 未被内部编辑器处理时收起悬浮栏，并将焦点返回右栏入口。
- 打开 / 关闭使用位移与淡入淡出，切换模式时同一面板连续移动和缩放；遵循动效 token 与 reduced-motion，不动画布局属性。固定栏保留分隔线，悬浮栏使用轻边框、圆角与浮层阴影。
- Todo 列表继续复用统一滚动边缘遮罩，固定标题和操作按钮不受遮罩覆盖。

## 6. 组件语义

### 6.1 `SurfaceCard`

当前主要用于：

- AI 卡片
- 空态容器
- 编辑块承托

规则：

- 不要把所有内容都套进 `SurfaceCard`
- 只有在确实需要层级抬升时才使用

### 6.2 `Button` / `IconButton`

规则：

- `primary` 只留给真正的确认或主要动作
- `secondary` 用于明确但不最高优先级的动作
- `ghost` 用于工具带与轻操作

### 6.3 `SearchField`

当前搜索是高频操作。

要求：

- 占位词直指对象范围
- 清除操作尽量就地
- 不额外包裹冗余标题

### 6.4 `StatusBadge`

用途：

- 对象类型
- 数量
- 辅助状态

规则：

- 用于补充语义，不代替主文本
- 不要堆太多不同色彩 badge

### 6.5 `RichEditor`

这是当前产品最重要的主组件之一。

它应呈现出：

- 清爽的正文编辑面
- 结构化增强而不抢戏
- 适合持续书写的阅读节奏

当前主要变体：

- `page`
- `bare`

## 7. 交互规则

### 7.1 首页连续性

- QuickNote 与 Record 同页展示，不提供视图切换按钮。
- 标题、封面和 QuickNote 的滚动关系由同一进度驱动；吸顶时使用平移与缩放连续过渡。
- 列表新增、删除、完成和筛选使用共享布局动画，避免后续内容瞬移。

### 7.2 选中态

选中态强调必须足够可见，但不应破坏整体温和基调。

适用于：

- 侧边栏当前项
- 顶栏当前页签
- 推荐浮层当前项

### 7.3 搜索与筛选

搜索和筛选是辅助定位，而不是主叙事。

因此：

- 应足够近
- 应足够轻
- 不应盖过正文工作面

搜索结果的进入、退出和重排复用共享列表动效；键盘连续选择与定位保持即时。

### 7.4 推荐浮层

Tag、Internal Reference 与 Contact Mention 在 Todo 和 RichEditor 中使用同一套轻量浮层：

- Tag 文案始终以 `#` 开头。
- 行高、圆角、图标、主副文字和选中态保持一致。
- 浮层宽度由内容和宿主可用空间共同约束，不因创建 Tag 输入而撑宽右键菜单。
- 通过 Portal 或可靠 stacking context 显示，不能被卡片、编辑器和有界滚动区裁剪。
- 已完成 Todo 不进入 Internal Reference 推荐。

### 7.5 窄窗口适配

当前产品在窄窗口下主要依赖：

- 页面宽度设置
- 侧边栏折叠
- Todo Rail 折叠

这些能力是正式交互，而不是调试工具。

## 8. 当前不建议的做法

- 把更多旧流程卡片继续堆回项目首页
- 为了“信息丰富”而增加厚重边框和说明文案
- 用系统原生粗糙控件破坏整体语气
- 在主编辑区上叠加太多颜色和状态层
- 把 AI 结果做成主视觉压过用户自己的笔记


## 列表排序与置顶

- Record 列表按最近修改时间降序排列；仅打开、查看或切换焦点不改变顺序。相同修改时间按 ID 降序稳定排序。
- Project 列表与 Workspace / Project Record 列表提供右键“置顶 / 取消置顶”。置顶项在前，两组内部仍按修改时间排序；不改变业务修改时间。
- 置顶是本机持久化的显示偏好，按 Workspace 根目录及 Project / Workspace Record 范围隔离。侧栏、记录焦点导航和主页记录卡片共享同一偏好。
- 工作区左侧记录菜单包含置顶、重命名和删除；重命名取消或无变化不提交，操作失败显式反馈。沿用统一右键菜单和下方滚动区域规范。
- 所有在用列表的置顶 / 标星状态统一为行右端 12px 次级文字色描边小图钉，复用 `ListPinIndicator`；不使用黄色实心星或放在标题前。记录卡片的标记独立于标题和悬浮操作区，会话运行指示放在标记前。
- Todo 提供右键置顶 / 取消置顶，按 Workspace 保存本机显示偏好；工作区聚合与项目视图共享同一 Todo 状态。只在原归属和完成状态分组内置顶，组内保留用户既有排序，不修改业务优先级或修改时间。
- 文件列表的版本号默认隐藏，行悬浮或键盘聚焦时显示；版本菜单打开期间保持可见。保留控件空间，避免挤动右端标记，尊重 reduced-motion。文件详情与固定历史 Tab 的版本提示保持原有行为。

## 滚动区域与边缘遮罩（默认规范）

- 所有有界滚动列表默认提供边缘遮罩，包括待办、项目、标签、最近记录、文件及搜索结果；工作区、项目、笔记页共用规则，无需逐页提出要求。
- 只在对应方向还有隐藏内容时显示：顶部有内容则显示上遮罩，底部有内容则显示下遮罩；内容不足一屏时两端都不显示。
- 上下遮罩高度为 `min(24px, 35%)`，左右遮罩宽度为 `min(16px, 35%)`（含横向 Tab 列表）；左侧导航列表的上下遮罩进一步收窄为 `min(16px, 35%)`。QuickNote 正文沿用 20% 的高度上限，最大高度同为 24px。遮罩使用区域底色渐变至透明。透明度由剩余滚动距离连续驱动：`clamp(distance / min(64px, maxScroll / 2), 0, 1)`，最多在最后 64px 内逐渐消失；不足 128px 的短滚动范围按实际距离归一化，保证起点/终点的另一侧遮罩仍达到完整强度。不得到达边界后才播放淡出动画，不得开关式跳变。
- 拖动滚动条、滚轮及反向滚动遵循相同规则；尊重减少动态效果偏好，不额外添加位移或延迟动画。
- 遮罩仅覆盖列表内容，不覆盖固定标题、搜索框、操作按钮或滚动条；不得阻挡点击、拖动、输入和浮层。
- 增删、完成待办、搜索过滤、展开子任务、切换范围以及容器尺寸变化后，应重新测量遮罩，不依赖用户再次滚动。
- 验收必查：无溢出、顶部、中间、底部、反向滚动、内容增删和调整尺寸。优先复用 `HomeSidebarList`（待办使用 `variant="todo"`），避免每个页面各写一套规则。

### 右键菜单（统一基准）

以左侧栏标签的“编辑标签 / 删除标签”菜单为标准。所有右键操作面板使用
`context-menu__panel`（子菜单为 `context-menu__submenu-panel`），操作行使用
`context-menu__item`，禁止各业务另写一套字号、行距和阴影。

- 面板：主题背景色、8px 圆角、细边框、`--shadow-md`、4px 内边距。
- 操作行：12px / 400，18px 行高，7px × 9px 内边距，5px 圆角；14px 图标与文字间距 8px。
- 普通项用次级文字色，悬浮和键盘焦点用浅灰底；危险项以 `data-tone="danger"` 标记红色文字，默认无红色底板。
- 保留轻微缩放淡入和 reduced-motion 支持；点击外部、Escape 关闭。
- 宽度按内容固定：短标签菜单 140px，通用菜单 176px，带标签编辑的文件菜单 240px，AI 输入面板 256px；展开标签不得撑宽面板。

本次排查覆盖：工作区/项目标签；项目、记录、顶部标签页；待办、子任务、进展；文件；富文本选区/图片/表格操作及子菜单、AI 输入、代码语言应用范围。通用操作走 `ActionContextMenu`，文件与输入类面板复用同一 CSS 基准，保留各自交互。系统原生文本编辑菜单不覆盖。
