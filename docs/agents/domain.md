# 领域文档

本文件说明工程技能在探索代码库时，应如何读取本仓库的领域文档。

## 探索前需要读取

- 仓库根目录中的 **`CONTEXT.md`**；或者
- 如果根目录存在 **`CONTEXT-MAP.md`**，它会指向各上下文的 `CONTEXT.md`，应读取与当前主题相关的文件。
- **`docs/adr/`** 中与准备处理的区域有关的 ADR。

如果这些文件尚不存在，**直接继续，不要提示**。不要报告文件缺失，也不要预先建议创建。`/domain-modeling` 技能会在术语或决策真正确定后按需创建它们。

## 文件结构

本仓库使用单上下文（single-context）布局：

```text
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-example-decision.md
│   └── 0002-another-decision.md
└── src/
```

## 使用术语表中的词汇

当输出内容需要命名领域概念时（例如议题标题、重构建议、假设或测试名称），应使用 `CONTEXT.md` 中定义的术语。不要改用术语表明确避免的同义词。

如果所需概念尚未出现在术语表中，这通常意味着两种情况之一：正在创造项目并未使用的语言，此时应重新考虑；或者项目确实存在术语缺口，此时应将其记录下来，交由 `/domain-modeling` 处理。

## 标记与 ADR 的冲突

如果输出内容与现有 ADR 冲突，应明确指出，而不是静默覆盖：

> _与 ADR-0007（event-sourced orders）冲突——但由于……值得重新讨论。_
