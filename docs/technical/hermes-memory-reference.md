# Hermes 长期记忆机制：源码参考

核对日期：2026-10-09。官方仓库 [`NousResearch/hermes-agent`](https://github.com/NousResearch/hermes-agent/tree/73162b00eefde3794bed0afb53d84a19c0eed230) 固定提交 `73162b00eefde3794bed0afb53d84a19c0eed230`（GitHub API `main` 当时返回的完整 SHA）。以下描述此版本的**实现事实**，不是 Project Mind 的既有能力或验收结果。Project Mind 的会话原文与摘要边界已在[会话记忆设计](../conversation-memory.md)定义；该文已引用 Hermes 较早提交 `3b0dc776` 的 `session_search_tool.py`，此处补全长期记忆机制，并以当前固定提交为准。

## 可复核的机制

| 环节 | Hermes 实现事实 |
| --- | --- |
| 分层与读取 | 内置 `MEMORY.md` 保存代理有关环境/惯例的笔记，`USER.md` 保存用户资料与跨任务偏好；默认字符上限分别为 2200、1375。`MemoryStore.load_from_disk()` 在会话起点读取文件并冻结系统提示词快照；同会话写入立即落盘，但旧快照不随之变化。工具没有 `read` 动作，响应可返回当前存储状态。外部 provider 的提示词块另行加入。见[存储与快照](https://github.com/NousResearch/hermes-agent/blob/73162b00eefde3794bed0afb53d84a19c0eed230/tools/memory_tool_store.py#L141-L211)、[系统提示词拼装](https://github.com/NousResearch/hermes-agent/blob/73162b00eefde3794bed0afb53d84a19c0eed230/agent/system_prompt.py#L516-L540)。压缩后重建提示词可重新加载磁盘记忆，故“冻结”不是整个长会话绝不刷新；见[重建入口](https://github.com/NousResearch/hermes-agent/blob/73162b00eefde3794bed0afb53d84a19c0eed230/agent/system_prompt.py#L813-L831)。 |
| 写入与纠正 | `memory` 工具提供 `add`、整条 `replace`、`remove` 以及原子批量 `operations`。`old_text` 仅用于定位一条唯一匹配的旧记录；批量按最终字符数检查容量。存储层加文件锁、重读、扫描危险内容，并对无法安全回写的外部漂移拒写。写入超额会返回待合并条目，连续整理失败有单轮停止上限。见[工具契约](https://github.com/NousResearch/hermes-agent/blob/73162b00eefde3794bed0afb53d84a19c0eed230/tools/memory_tool.py#L345-L427)、[匹配逻辑](https://github.com/NousResearch/hermes-agent/blob/73162b00eefde3794bed0afb53d84a19c0eed230/tools/memory_tool_store.py#L72-L102)、[事务式修改](https://github.com/NousResearch/hermes-agent/blob/73162b00eefde3794bed0afb53d84a19c0eed230/tools/memory_tool_store.py#L303-L354)、[批量检查](https://github.com/NousResearch/hermes-agent/blob/73162b00eefde3794bed0afb53d84a19c0eed230/tools/memory_tool_store.py#L472-L524)。这是一套**显式条目修改机制**，不能从中推断已对历史会话、衍生结论或外部 provider 做删除传播与防复生。 |
| 自动记忆提取 | 对话后的 background review 可由模型挑选值得记住的内容，调用同一个 `memory` 工具；提示词将 USER 与环境记忆分流，也把任务类别的程序性经验引向 skill。默认自动审阅可关闭或路由到其他模型。内置文件的“自动”仍是模型判断后发工具调用，并非所有消息自动抽取入库。见[审阅提示词](https://github.com/NousResearch/hermes-agent/blob/73162b00eefde3794bed0afb53d84a19c0eed230/agent/background_review.py#L357-L380)、[工具范围](https://github.com/NousResearch/hermes-agent/blob/73162b00eefde3794bed0afb53d84a19c0eed230/agent/background_review.py#L1079-L1115)、[用户文档](https://github.com/NousResearch/hermes-agent/blob/73162b00eefde3794bed0afb53d84a19c0eed230/website/docs/user-guide/features/memory.md#L315-L356)。外部 provider 有独立的 `sync_turn`、`on_session_end` 和 `on_pre_compress` 等接口；会话结束提取与切换在单 worker 顺序执行，见[接口](https://github.com/NousResearch/hermes-agent/blob/73162b00eefde3794bed0afb53d84a19c0eed230/agent/memory_provider.py#L133-L180)、[边界提交](https://github.com/NousResearch/hermes-agent/blob/73162b00eefde3794bed0afb53d84a19c0eed230/agent/memory_manager.py#L742-L778)。不要把可选 provider 的提取能力归于内置两文件。 |
| 写入审阅 | 可选 `write_approval` 会把写入暂存。待审的 `replace`/`remove` 固定其完整目标条目；批准时若目标已变化则拒绝应用。无人值守的 background review 即使普通写入门关闭，替换与删除也会暂存。见[暂存与固定目标](https://github.com/NousResearch/hermes-agent/blob/73162b00eefde3794bed0afb53d84a19c0eed230/tools/memory_tool.py#L64-L111)、[后台删除门](https://github.com/NousResearch/hermes-agent/blob/73162b00eefde3794bed0afb53d84a19c0eed230/tools/memory_tool.py#L165-L211)、[批准重放](https://github.com/NousResearch/hermes-agent/blob/73162b00eefde3794bed0afb53d84a19c0eed230/tools/memory_tool.py#L326-L343)。 |
| 会话检索 | `session_search` 读取 SQLite 会话库：FTS5 发现按会话谱系去重，互动会话优先于定时任务；结果有受限上下文，另用消息锚点滚动或会话 ID 读取。已压缩、重置而离开当前上下文的消息仍可发现；当前活跃上下文通常被排除。索引重建状态在响应中明示。见[工具模式](https://github.com/NousResearch/hermes-agent/blob/73162b00eefde3794bed0afb53d84a19c0eed230/tools/session_search_tool.py#L1-L55)、[发现与排序](https://github.com/NousResearch/hermes-agent/blob/73162b00eefde3794bed0afb53d84a19c0eed230/tools/session_search_tool.py#L354-L432)、[锚点窗口与分发](https://github.com/NousResearch/hermes-agent/blob/73162b00eefde3794bed0afb53d84a19c0eed230/tools/session_search_tool.py#L521-L616)、[覆盖状态](https://github.com/NousResearch/hermes-agent/blob/73162b00eefde3794bed0afb53d84a19c0eed230/tools/session_search_tool.py#L314-L324)。 |
| 压缩 | 压缩属于活跃上下文管理；外部 provider 的 `on_pre_compress` 可给摘要提示词补充记忆上下文。需要 v2 检查点时，找不到兼容 provider 或检查点失败会阻止该次压缩，以保留未压缩记录；普通调用中的 provider 错误可被忽略。内置 `MEMORY.md`/`USER.md` 本身不会因容量满而自动压缩。见[压缩前 provider 调用](https://github.com/NousResearch/hermes-agent/blob/73162b00eefde3794bed0afb53d84a19c0eed230/agent/conversation_compression.py#L2930-L2967)、[manager 检查点](https://github.com/NousResearch/hermes-agent/blob/73162b00eefde3794bed0afb53d84a19c0eed230/agent/memory_manager.py#L795-L841)、[文档中的容量说明](https://github.com/NousResearch/hermes-agent/blob/73162b00eefde3794bed0afb53d84a19c0eed230/website/docs/user-guide/features/memory.md#L23-L35)。 |

## 对 Project Mind 的借鉴判断（建议，非 Hermes 事实）

- 沿用 Project Mind 已有的“原文搜索 → 有界回读 → 派生知识”链路；可借鉴 Hermes 的会话降噪排序、压缩后历史可发现性与覆盖状态提示。Project Mind 的 Pi JSONL 权威、Project/Workspace 授权、来源依赖与 AI 排除规则仍应由自身可信 Host 执行，不能移植 Hermes 的 profile 或 lineage 判定作为权限。
- 可将高频且稳定的用户偏好与环境事实放入受预算约束的短记忆，任务过程和原话仍留在可回读来源；用户纠正宜有精确目标、版本/并发校验和可见结果。Hermes 的冻结提示词说明新写入何时可见需要产品定义，不能把“工具调用成功”误称为当前所有会话已经使用。
- 自动审阅是一个候选提取入口，不是事实真实性、用户决定或原生操作成功的证明。Project Mind 的摘要/Overview 已有来源和收据约束，应继续保留；删除、排除后的检索与衍生内容失效尤其不能仅靠 Hermes 的 `remove` 推断完成。
