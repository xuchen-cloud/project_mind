# Voice Record 持久补转写与实时控制验收（2026-11-01）

关联 [#296](https://github.com/xuchen-cloud/project_mind/issues/296)、[需求](../requirements/voice-durable-transcription.md)。基线 `7e9b5b65`，保留 #293 / #295 的异步识别和增量 FSMN。

## 实现与完整性边界

- 原始双轨采集与持久写盘独立于实时识别。关闭实时转写不重启采集，不改 capture epoch；消费线程继续排空识别副本，关闭 VAD/ASR 计算。控制代次使已过期的排队任务不开始推理，已运行模型的迟到结果不能恢复旧字幕或跨区间重复写入。
- 手动选择和自动抑制分开持久化。自动过载先让预览让位于最终识别，达到有界积压阈值后关闭实时识别；暂停、重启、新录音均不自动恢复。只有显式手动操作清除抑制；普通设置保存不能误恢复。
- 控制命令在持久事务中校验 session/revision，提交偏好、缺口与新 revision 后才改变运行状态。已结束的采集 epoch 不接受新的开放缺口，避免暂停中切换产生永远无法封口的任务。
- 本地恢复复用原云端任务表，以明确 backend 区分。任务认领带递增租约；Transcript、完成游标、扫描游标和有限的分段/句子中间状态一起提交。过期结果或重复提交整个回滚；Record 正文不参与恢复写入。
- 恢复按有限音频窗口扫描，复用 10 秒最大分段、350ms 重叠和 SentenceAssembler；30 秒持久检查点不会强行切断句子。WAV 格式、长度、双路来源及内部缺口均验证；已知首回调前和末回调后的时间轴空白保持静音语义。
- 停止采集、结束写盘后即可返回；本地推理线程由后台回收持有，任务从持久 frontier 补齐。原生推理无法安全强杀：超时或取消使结果无效，但仍保留所有权直到调用退出；全局推理门限避免退役任务与补转写同时占满 CPU。
- Activity 使用两路共享的故障开关。辅助队列满、消费者关闭或处理失败会关闭自动静音暂停及后续副本投递；原始队列、设备、解码、时间轴与写盘错误仍沿原保护路径处理。
- 外部展开浮窗与设置菜单显示当前实时识别状态，应用内改为横幅。横幅跨页面定位实际 Record，Project 独立窗口则通过主窗口导航。外部结束先保存、再恢复并聚焦主窗口、定位 Record；打开失败保留已结束目标供重试，不重复结束。横幅不等待后台文字补齐；音频保存失败仍等待重试时，横幅/浮窗保留明确保存状态并禁用重复采集命令。

## 真实音频与性能

同一份约 57.297 秒的私有双轨 WAV，只读原件；恢复测试使用临时 Workspace、音频副本和模型链接。日志仅记录哈希、计数、时间和性能；用于对照的文字导出保存在本机临时目录、权限 0600，不进入仓库。

真实 SenseVoice 恢复：完整执行与在 30 秒检查点后关闭/重开数据库继续，7 条最终 `(start,end,text)` 完全相同，SHA256 `c77784ef04eea0ecce97e1387ec13cdda2d380ec3b4d4fa25a5049b6982bce2f`。最终游标 57297ms、状态 ready；每次重复提交均拒绝；用户已编辑 Record 的完整序列化视图保持不变。初次双运行总耗时 26.31s（不是单次推理 RTF）。

本次开启/关闭对照的录音阶段测试进程 CPU 时间减少 **66.4%**；该指标包含模型初始化、回放准备及两路 Activity，并非整机 CPU 百分比。真实时间约 60–61 秒包含 57.3 秒按实时速度喂入，不能用其差值宣称推理加速。单组测量不承诺其他机器同样比例；关闭实时转写把识别工作延后到停止录音后。

最终恢复重跑也通过，双路径合计 14.50s；温缓存等环境因素使其与首轮耗时不同。原件保持只读。机器外推以 #294 实测为准。
