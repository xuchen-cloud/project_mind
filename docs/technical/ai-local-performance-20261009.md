# AI 本地性能与观测验证（2026-10-09）

本记录对应交付工作包 S4、Issue #107 的本地验证。它不替代真实 Provider、用户实际项目或 macOS/Windows 安装验收，也不以测试数量表示产品完成比例。

## 环境与语料

- 应用版本 0.1.4，代码基线 `9b9734d` 加本工作包改动；Rust 使用开发容器中的 debug/test 构建，内置 SQLite 3.51.3。
- Linux 6.18.44，x86_64，Intel Xeon Platinum 8573C；容器配额 4 CPU、16 GiB 内存。
- 3000 条真实保存的 canonical Record、200 个导入的文本 File。使用生产 Record 与来源提取 worker 建立索引，3203 个索引任务全部完成；额外任务来自夹具中的项目和 Todo 等对象。
- 保留语料使用 SQLite backup 和文件复制，数据库完整性检查通过。复测既检查搜索有实际结果，也通过 `source.read` 读取 File 正文；不是只搜索标题或用模拟结果计时。
- 最初建库与索引约 35 分钟，期间夹杂其他验证负载，不能当作独占环境下的冷态性能指标。查询采用 10 次预热、100 次测量，下面的 p95 为第 95 个排序样本，不包括模型响应。

## 查询结果与修复

| 场景 | 热态 p95 | 目标 | 结果 |
| --- | ---: | ---: | --- |
| 大语料、已发布非空 Overview 的 `context.get` | 9.735ms | ≤300ms | 通过 |
| 同库 Record 搜索 | 135.203ms | ≤500ms | 通过 |
| 同库 File 搜索 | 73.931ms | ≤500ms | 通过 |
| 已发布非空 Overview 的知识状态（较小夹具） | 4.894ms | ≤200ms | 通过 |

大语料的非空概览通过真实 Record 搜索、正文读取和 `CapturedEvidence`，经 `OverviewService.publish` 发布；只是基于该条实际依据的小概览，不代表已整理全部语料。测量走实际 `context.get` 分发，断言返回非 NotBuilt 状态及真实来源正文。该组 p50 为 6.448ms，最大值为 12.547ms。最初尚未建立概览时测到的 2.823ms 只记录为 NotBuilt 路径证据，不用于代替非空概览验证。

规模验证发现并修复两处实际问题：

1. 缓存归属清理把数据库主键转为文本再比较，执行计划扫描业务表。现在增加可使用主键的数值条件，同时保留原来的精确文本匹配，避免改变 ID 归属语义。
2. 内置 SQLite 在全文查询中先遍历来源和内容块，再为每个块扫描全文索引。明确采用全文索引 → 内容块主键 → 来源主键的连接顺序后，Record 首次查询由约 13.2 秒降至约 148ms。权限、排除、版本和真实文件验证仍执行。

一次中间 File 测量在后段出现六个超过 500ms 的样本，提前判定失败。之后三次分段查询未复现；无其他测试或编译同时运行的完整复测中，Record/File p95 分别为 269.106ms / 97.577ms；随后补充非空概览的同库完整复测得到上表结果。此前长尾的原因尚未确定，不归因于未经证实的系统负载，也不通过放宽阈值处理。269.106ms / 97.577ms 那轮复测期间 cgroup 的节流次数和节流时间没有增加；load average 从 1.24/2.00/1.50 变为 1.11/1.89/1.48。此记录证明本机样本达标，不承诺所有机器和资料都具有相同延迟。

## 本机日志与超时

本机日志位于 Workspace 的 `.project-mind/logs/ai-operations.jsonl`，达到约 1MiB 时轮转到 `ai-operations.previous.jsonl`，只保留上一份。字段只有时间、固定操作名称、耗时、数量和稳定结果码，不写问题、正文、来源路径、凭据或模型推理，也没有远程上传。

日志接在来源检索/读取、引用解析、成果保存、会话恢复和取消结算边界。取消耗时从用户请求被接受开始计算；日志文件写入放在数据库锁外。真实落盘、错误码和连续两次轮转已有定向测试。没有把日志写入器测试宣称为真实 GUI/AppBridge 全链路运行验收。

超时使用独立的 `TIMED_OUT`，与容量或调用次数达到上限的 `BUDGET_EXCEEDED` 区分。内部 `session.context.check` 不再延长首响应期限。前端说明超时后已保存消息或整理进度仍保留；Node 工具请求超时会取消 SDK 并保留 checkpoint。这里验证的是确定性执行路径，未等待真实 Provider 超时。
