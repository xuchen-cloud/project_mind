# Project Mind Alpha 产品 PRD

## 1. 文档定位

这是一份基于当前代码实现整理的现状基线 PRD，用来描述 Project Mind Alpha 已经具备的产品能力、当前明确未做的范围，以及接下来 `1` 到 `2` 个版本的演进方向。

本文档只记录三类内容：

- 当前前台已经可用的能力
- 数据层或设置层已经存在、但前台尚未完整暴露的能力
- 与现有架构优化方向直接相关的近期规划

不再保留与当前系统不符的理想态功能描述。

## 2. 产品定位

Project Mind Alpha 是一个本地优先的项目推进工作台。

它不是通用笔记工具，也不是完整的项目管理平台。当前产品核心目标是：

- 围绕 `Project` 组织项目推进过程中的资料、记录和结果
- 围绕 `Activity` 承接一次具体会议、评审、对齐或处理动作
- 把原始记录沉淀为 `Conclusion` 和 `Todo`
- 让用户在项目级持续看到当前状态，而不是反复翻会议纪要

当前技术形态为：

- 桌面应用：`Tauri + React + TypeScript`
- 本地结构化数据：`SQLite`
- 本地文件托管：项目目录与受控文件路径
- 本地优先，不依赖服务端运行

## 3. 目标用户

当前产品主要面向以下用户：

- 项目负责人
- 产品经理 / 方案经理
- BA / 跨团队协调者
- 需要频繁开会、整理资料、跟踪后续动作的人

核心使用场景是：

- 在项目内连续记录活动过程
- 从记录中沉淀结论与待办
- 持续追踪未完成事项
- 把文件材料挂到项目或活动上下文中
- 通过 AI 生成候选结论 / 待办，并由用户确认采纳

## 4. 当前信息模型

### 4.1 核心对象

- `Project`
  - 项目容器
  - 包含名称、状态、根目录、摘要、归档状态
- `Activity`
  - 项目中的一次具体工作事件
  - 包含标题、时间、活动属性、活动状态、折叠状态、固定展开状态
- `Note`
  - 活动内原始记录
  - 当前仅支持 `quick_note` 与 `meeting_minutes`
- `Conclusion`
  - 活动中沉淀出的明确结论
  - 可标记为“提升到项目首页”
- `Todo`
  - 项目或活动范围内的待推进事项
  - 当前为两态：`unfinished` / `finished`
- `TodoProgress`
  - Todo 的阶段性进展记录
- `Document`
  - 项目级或活动级文件材料
  - 当前包含托管路径、原始路径、标星状态、健康状态、版本计数
- `AI Profile / Binding`
  - AI 接入配置、能力绑定和密钥存储策略
- `Rich Text Style Settings`
  - 富文本正文、标题、列表的全局排版配置

### 4.2 当前关系

- `Project` 1:N `Activity`
- `Activity` 1:N `Note`
- `Activity` 1:N `Conclusion`
- `Project` 1:N `Todo`
- `Todo` 可选关联 `Activity`
- `Project` 1:N `Document`
- `Document` 可选关联 `Activity`
- `Todo` 1:N `TodoProgress`

## 5. 当前已实现能力

### 5.1 Workspace 与导航

- 顶部工作台支持展示活跃项目页签
- 支持从顶部入口创建新项目
- 支持查看归档项目列表并恢复项目
- 支持全局设置入口
- 支持顶部工作台搜索，覆盖：
  - 项目
  - 活动
  - 结论
  - Todo
  - 文件

### 5.2 项目管理

- 支持创建项目
- 创建时在指定目录下生成项目文件夹
- 支持编辑项目摘要
- 支持项目归档与恢复
- 支持在项目页查看：
  - 项目摘要
  - 项目级文件区
  - 结论时间线
  - 项目级 Todo Rail

### 5.3 Activity 管理

- 支持在项目页内创建 Activity
- 当前创建字段为：
  - 活动属性，可选
  - 标题
  - 时间
- Activity 详情页当前支持：
  - 查看标题与时间
  - 调整活动属性
  - 调整活动状态
- 活动状态来自可配置字典，由名称和固定颜色组成
- 活动列表和侧边栏使用对应颜色标签展示状态

### 5.4 Note 记录

- 每个 Activity 下支持多条 Note
- 当前 Note 类型仅包括：
  - `quick_note`
  - `meeting_minutes`
- 支持在活动页创建、编辑和切换已有记录
- 支持将文件插入到富文本记录中
- 支持在记录编辑器中打开或定位插入的文件资源

### 5.5 结论沉淀

- 支持在 Activity 页手动新增 Conclusion
- 新增结论时可选择是否提升到项目首页
- 支持在项目页按活动分组浏览结论时间线
- 支持在项目页对已有结论做行内编辑

### 5.6 Todo 管理

- 支持在项目级创建 Todo
- 支持在 Activity 级创建 Todo
- Todo 当前字段包括：
  - 内容
  - 两态状态：`unfinished` / `finished`
  - 优先级
- 支持：
  - 更新内容
  - 切换状态
  - 追加进展记录
- 项目页和 Activity 页都通过侧边 Todo Rail 展示未完成与已完成事项

### 5.7 文件管理

- 支持在项目级或 Activity 级导入文件
- 当前导入行为为复制到项目受控目录
- 支持点击文件打开托管文件
- 支持双击文件名重命名 `baseName`
- 支持标星 / 取消标星
- 支持识别文件健康状态：
  - `normal`
  - `missing`
- 当文件存在多个版本计数时，UI 会展示当前版本徽标 `vN`

### 5.8 搜索

- 当前搜索入口位于顶部工作台
- 当前搜索结果可跳转到：
  - 项目总览
  - Activity 页面
  - 指定结论锚点
  - 指定 Todo 锚点
  - 指定文件锚点

### 5.9 AI

#### 已实现的前台能力

- 支持在设置页配置 AI provider profile
- 支持测试模型连通性
- 支持配置能力绑定
- 当前前台实际消费的 AI 能力为：
  - 从单条 Note 生成候选结论
  - 从单条 Note 生成候选 Todo
  - 用户确认后写入当前 Activity

#### 当前支持的 provider family

- `OpenAI-compatible`
- `Claude-compatible`
- `Gemini-compatible`

#### 当前安全能力

- API Key 采用设备绑定加密存储

### 5.10 设置

当前设置页分为五个分区：

- `活动标签`
  - 管理活动属性字典
  - 管理活动状态字典
- `文件标签`
  - 管理 workspace 级文件标签字典
  - 为文件列表筛选、导入和右键打标签提供复用源
- `记录类型`
  - 管理记录类型名称、颜色和模板
  - 名称与颜色自动保存，模板内容在编辑器中自动保存
- `AI 设置`
  - 管理 provider profile
  - 管理能力绑定
  - 查看本地安全模式
- `富文本样式`
  - 配置正文、标题、列表的字体、字号、行距和段前后距

## 6. 已建模但未完整暴露的能力

以下能力当前在数据层、设置层或接口层已经存在，但前台没有形成完整用户能力，不应写成“已实现”：

- 文档版本管理
  - 数据模型里已有版本字段与版本记录接口
  - 当前前台只展示版本徽标，不提供版本列表和显式新增版本入口
- AI 多能力绑定
  - 设置里已有 `default / assistant / summary / suggestion_generation`
  - 当前前台真实使用的是 `suggestion_generation`
  - `assistant` 与 `summary` 尚无对应产品流程
- 活动标题建议
  - 后端 suggestion 类型包含 `activity_title`
  - 当前前台主要展示和采纳的是结论 / Todo 候选
- 文档重新定位
  - 后端已有 `document_relocate`
  - 当前前台尚未提供完整的“重新定位失效文件”入口
- 历史 legacy 迁移兼容
  - 数据层仍保留部分历史字段与迁移逻辑，用于兼容旧数据

## 7. 当前明确未做

以下内容当前不属于已实现范围：

- 活动分类模板体系
- 文件角色 UI
- 五态 Todo
- Todo 截止时间
- Todo 描述字段
- 项目级 Conclusion 创建入口
- Activity 级 AI 总结页
- AI assistant 对话流程
- 文档版本历史 UI
- 导出
- 云同步
- 多人协作
- 权限体系
- 高级筛选系统

## 8. 当前产品约束

### 8.1 交互约束

- 结论的新增入口当前位于 Activity 页，不在项目页直接创建
- Todo 是结构化对象，不内嵌在纪要正文中管理
- 工作台搜索是统一入口，当前没有单独的复杂筛选面板
- 文件健康状态可见，但修复入口尚未完全开放

### 8.2 架构约束

- 当前前端业务编排较多集中在页面组件和 mutation hooks
- React Query 失效策略仍偏手工
- Tauri 后端仍以集中式命令与数据库对象为主
- 部分 legacy schema 和未使用接口尚未清理

## 9. 下一阶段演进

以下规划只覆盖未来 `1` 到 `2` 个版本，并直接对齐当前架构优化方向。

### 9.1 AI 工作流作业化

- 将当前同步式 AI 命令升级为作业系统
- 支持开始、取消、状态查询、失败重试
- 为后续流式反馈与更重的 AI 工作流预留边界

### 9.2 后端分层

- 把当前集中式数据库对象拆分为：
  - commands
  - repositories
  - domain services
  - file / AI infra
- 缩小数据库锁作用范围，减少长耗时 I/O 对整体响应的阻塞

### 9.3 前端查询层收敛

- 收敛 query key 定义
- 减少页面内散落的 `invalidateQueries`
- 逐步把页面编排下沉到 screen hooks 或组合层

### 9.4 遗留与冗余清理

- 清理不再被前台消费的命令和状态
- 明确 legacy 字段只用于迁移兼容，不再继续扩散到新逻辑
- 统一前后端契约来源，减少双端模型漂移

## 10. 文档使用原则

从当前版本开始：

- 本文档是产品现状与近期规划的基线
- 任何新功能进入本文档之前，必须先在代码或明确实现方案中有事实依据
- 数据层预留能力必须明确标注为“未完整暴露”或“后续规划”，不得直接写成“已实现”
