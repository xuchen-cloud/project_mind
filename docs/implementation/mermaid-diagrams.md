# Record / Markdown Mermaid

Work item: [#301](https://github.com/xuchen-cloud/project_mind/issues/301), review group G16.

## Rendering and source

Both editors use the existing Mermaid 11 renderer and `renderSafeDiagram`. Mermaid remains a dynamic import. Diagram source stays in the codeBlock, with `language: mermaid`; live SVG is a NodeView projection and is never serialized into Record content. Markdown keeps its fenced source through the current source/block editor modes. On develop, legacy split/preview view values map to block editing; the retained safe preview adapter has direct regression coverage. G16 does not restore the removed split UI.

Record's normal code language picker includes Mermaid. In a rendered block, click the diagram or use its keyboard action to view/edit source; read-only content supports source inspection. Invalid syntax shows an error and keeps source visible. Source, language, document, theme changes and destruction invalidate pending results. Source edits debounce rendering by 300 ms.

G01 owns Record canonical / HTML language roundtrip. This group does not introduce a second parser or a separate persistence representation. Its integration gate is the records group's reviewed contract, followed by canonical save/reopen verification.

## Visual direction

Reference: [beautiful-mermaid themes](https://github.com/lukilabs/beautiful-mermaid/blob/main/src/theme.ts). The zinc neutral hierarchy and GitHub blue accent were evaluated as visual references. No beautiful-mermaid dependency or source implementation was copied. Its limited renderer is not used as a substitute for Mermaid syntax.

The selected adaptation uses Project Mind's warm background and ink colors, restrained borders, blue secondary accents, CJK font fallbacks, 15 px labels, increased node spacing and smooth connectors. A separate dark palette retains readable text and line contrast. All theme values enter Mermaid's SVG generation, following the [Mermaid base theme configuration](https://mermaid.js.org/config/theming.html). No host-only CSS recoloring or remote font imports are required.

Mermaid has global configuration, so initialize and render execute in one serialized queue. Preview requests pass the host theme; document exports explicitly use light. SVGs therefore retain their own theme outside the host. The host theme resolver supports `data-theme`, a root `dark` class, and an explicit root `color-scheme`.

## Export boundary

- Markdown exports the fenced source, including internal blank lines, trailing newlines and embedded backtick runs.
- Markdown print/PDF/PNG and DOCX share the existing safe SVG pipeline. DOCX no longer calls the raw renderer before checking resource syntax.
- Record DOCX/PDF prepare safe diagram PNGs in the coordinator before allocating a generator or worker. Generated bytes count toward the existing workspace budget. The derived export model changes; persisted source does not.
- Syntax errors, blocked resources or unavailable raster decoding retain readable code in the artifact. Cancellation is checked before and after asynchronous rendering/raster steps.
- DOCX/PDF fit tall diagrams proportionally within the printable area. PDF measurement and drawing use the same dimensions and reserve caption space.

## Reproducible browser fixture

Run the package preview Vite config and open `mermaid-preview.html`. It compares the old default, a blue-accent candidate and the selected warm neutral, then exercises the public Record and Markdown components. It opens no native workspace or user data.

Fixtures in `packages/markdown-editor/tests/fixtures/mermaid.ts` cover Chinese long-label flowcharts, sequence diagrams, a long sequence, and Gantt syntax beyond the candidate renderer's supported subset. Local screenshots and generated SVG/PNG/DOCX/PDF evidence live under ignored `output/playwright/mermaid/`.

## Verification ledger

The final checks, exact commit and dependency status are recorded in the review handoff's `status/mermaid.json`. Full Office compilation is outside this group; a failed upstream Office download must not be reported as a successful full build. Frontend compilation can reuse the existing Office renderer distributions without rebuilding or changing their sources.

On 2026-11-10, the independent checks passed 44 Record tests, 21 Markdown export/theme/preview tests, and one actual DOCX/PDF geometry test. The geometry test decodes a generated PDF and inspects DOCX image extents; tall images preserve aspect ratio, stay within A4 margins and leave room for a caption. Real browser artifacts also cover SVG decoding, PNG rasterization, and a long sequence exported to DOCX/PDF. Browser timings are a single warmed macOS Chrome sample recorded in `browser-summary.json`, including the main-thread timer gap; they are not a Windows, release, or percentile claim.

The two workspace/project canonical save/HTML/reopen tests remain a strict G01 integration gate. Before #302 is merged, they fail on the known language parser contract. Do not skip them or mark this group mergeable until the dependency is rebased and those tests pass.
