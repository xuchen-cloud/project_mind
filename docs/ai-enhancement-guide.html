01 / 全貌

助手要帮你完成的三件事

先认识三个名字：工作区（Workspace）是一整套资料库，项目（Project）是其中一项工作的范围；笔记、待办和文件在代码中分别叫 Record、Todo、File。

当前内置助手可从项目或工作区入口工作：回答“资料里说了什么”，找回“以前为什么这样决定”，并把这次讨论落实为可继续编辑、可找回、可撤销的成果。普通提问从小范围入口开始，证据不够才继续读取原文。

01 / 查资料

给答案，也给来处

从 Record、File 等已授权材料寻找依据；需要时读对应版本和局部正文。资料不完整就说明覆盖范围，不能把摘录当全文。

02 / 找旧讨论

找回决定的上下文

先检索会话目录和摘要，再回读相关原话。过去的建议、计划和用户明确决定要分清，不把“提过”说成“定了”。

03 / 留下成果

保存成真正的笔记、待办和文件

把认可的方案保存为 Record、Todo 或 File，返回可打开的成果，以及实际保存的操作记录。下一轮可以接着改同一对象，历史版本还在。

目前这条路线的底层服务和不少界面已存在；“可以调用”“用户在正式安装的应用中顺畅完成”是两个不同结论。下面逐项标出。

03 / 一项请求

从一句话到实际保存的成果

例如：“根据会议纪要更新发布计划，再创建三项待办。”下面这条执行链已接入代码，仍需用真实模型和正式安装包走完整个任务。

  1. 找依据
    查会议纪要，读当前计划；先知道要改什么。
  2. 说清方案
    说明准备更新哪份计划、增加哪些行动，细节按需展开。
  3. 确认一次
    同一方案只决定一次，不要求你逐段、逐工具审批。
  4. 保存成果
    应用检查版本后逐项保存，告诉你哪些成功、哪些失败。
  5. 继续或撤销
    打开真实笔记和待办接着改，也可以恢复任务前的内容。

模型提出修改方案，应用自己的保存服务负责真正写入。只有保存成功的操作记录才算完成。模型说“已经修改”本身不算凭据；中途失败也不能把已经保存的部分说成没发生。

只读

可以找资料、分析和回答，不允许创建或修改成果。

默认：确认后执行

先给简短方案，你确认后执行。补充修改要求会让旧方案失效。

主动选择自动执行

你启用这个模式后，助手在已有权限内直接保存；版本和冲突检查仍保留。

本地实现进展：文字回复现会进入当前 Pi 会话，由模型结合当前方案判断确认、修改、取消或提问，再按需调用决定工具；不靠固定短语识别。按钮仍可直接确认，并与工具共用持久决定和原生保存。Rust、界面及 Host 定向检查已通过；真实模型服务下的连续会话仍待验收。
04 / 会话管理

一段对话，可以连续完成多次任务

你可以在同一段会话中先问资料，再讨论方案，最后修改成果。每次发起任务，系统会记录一次执行过程，代码里称它为 Run。一次会话包含多次任务，一次任务又可以产出多份笔记、待办或文件。

工作区
整套资料库›当前项目
助手工作的范围›会话
围绕一件事持续讨论›一次任务
一轮执行及其成果

原话保存一份，搜索另外建目录

Pi 把对话逐行保存为 JSONL 文件，这是原文。SQLite 数据库保存会话列表和搜索索引，方便快速找到相关消息。搜索到线索后，再读对应原文；不会把一小段搜索摘录当成全部语境。

收起、停止和继续各有含义

收起面板不取消已经确认的多项保存；隐藏期间暂停更新屏幕上的流动文字，重新打开后会显示最后内容，并保留草稿、阅读位置和已展开的内容。运行中可以继续写草稿；要发送新消息，先停止，等正在保存的操作处理完再发送。重开会话可以继续，已经保存的成果不能重复写一次。

历史列表和搜索让你回到以前的讨论。历史树中的旧分支也能进入索引，但当前不能据此宣称已有“任意消息分叉编辑”的界面。模型为长对话压缩上下文，也不能代替下节的历史检索和记忆。

项目助手只读取当前项目；工作区助手按每轮开始时的活动授权项目集合读取资料，翻看历史或切换业务页面不会自动扩大授权。强制退出后恢复、网络故障后续聊等已有相关实现，真实模型与目标系统下的完整体验仍待验收。

05 / 记忆如何形成

需要多少依据，就往下读多少

新会话不会把整个 Project 或所有 Project 概览塞给模型。工作区助手先用有界项目列表寻找相关项目，再按需读取；项目名称和 ID 也记入本轮来源。项目排除或归档后，旧会话的相关来源不再向 AI 展示。助手先看到有限目录，查到相关主题再取概览或分段摘要；没有摘要时也可以直接搜索原文；若问题是“上次原话是什么”，就定位并读取相关消息。证据足够就停止读取，来源失效或只读了摘录就如实说明。没有搜到摘要也不能断言“从未讨论过”。

例子：问“为什么暂缓权限管理”，读取路线可能是：决定入口 → 相关会话摘要 → 作决定前后的几条原始消息 → 带来源的回答。它不要求通读全部聊天记录。

用户 QuickNote 与 AI Overview 分开。QuickNote 是用户自己的临时记事，沿原有编辑保存；Overview 是独立的 AI 派生概览，不改写用户原文。历史索引只是“找得到消息”的目录，也不是总结。会话摘要会区分计划、建议、明确决定、用户报告和实际保存成功的操作，并附可追溯来源。

资料变化和新消息会进入待整理队列，维护服务分批处理，并记录做到哪里；取消或失败时，保留已有结果和进度，之后可以继续。

普通对话的 Pi 原生压缩已在代码中启用；使用真实 SDK 和模拟模型的测试已触发压缩，并验证保存和恢复。仍需真实模型服务验收。跨会话搜索仍靠原文索引。Pi 的压缩内容是一段续聊用的自由文本，没有每条判断的来源和纠正记录，不能直接当作项目知识；生成项目概览的单次调用会关闭压缩，保留所读依据，必要的知识仍按有来源的消息段增量整理；当前分支的完整短消息现可合批，历史分支和长消息仍单独处理。项目每日五次、工作区每 20 分钟二十次、每批三次及累计 48k 字符的任意额度已从调度代码移除；单次完整请求会按模型容量分配输入空间，未知模型别名使用默认容量；长内容会继续分段。失败会停止并保留进度，人工恢复可继续。读取接口的 50 条消息 / 12000 字符只是当前单页大小，不是摘要长度或产品标准。失败时保留进度，之后有限续跑；原文搜索仍可用。

Workspace 分层知识已在本地接通并通过定向检查。它从已发布的 Project 概览条目和工作区直属资料逐步更新：项目条目保留所属项目、概览版本和可展开的原始依据；直属笔记、待办和会话仍沿原来源路径。已启用的项目按自己的安排整理，其他活动项目可随工作区安排整理；一个项目失败或延期时，其余项目与直属资料仍可推进。三项目的可见性、来源读取、纠正后旧版隐藏和草稿重放已有本地定向证据；补充服务检查还覆盖父条目删除、只更改一个项目和一条直属笔记、文件仅改名，以及长内容逐页遵守用户纠正。真实模型与目标平台验收仍待完成。

长期记忆的本地实现与检查已完成，产品验收尚未完成。参考 Hermes 长期记忆源码研究，它把有长期价值的内容分为背景、领域、兴趣、方法、偏好和知识线索六类；具体讨论和原话仍可按需搜索。助手整理出的条目始终标为“推断”，只有用户亲自确认才显示“用户已确认”。用户可以查看依据、纠正正文、停用或重新启用；纠正留下新版本，原来的版本仍在历史里。停用针对同一范围、同类记忆及相同原始来源，防止下一次整理换个标题又写回来。若几条停用决定同时生效，重新启用一条不会解除其他决定。旧会话和旧知识版本也要按最新决定过滤；原始笔记和讨论仍按原有授权可搜索。数据库、界面和浏览器的本地检查已有通过证据；真实模型和目标系统尚未验收。

AI 排除、删除和授权缩小会过滤搜索、原文读取和派生结论；不能只藏来源链接却继续露出由它推得的结论。用户在应用界面查看自己的原始历史另有规则。已经发给外部模型提供方的内容无法追溯撤回。

因此，模型没有直接绕开应用去写数据库。内置助手与外部工具都要遵守相同的对象归属、版本和保存规则，修改失败时也使用同一套恢复机制。

项目资料保存在本地；调用配置的模型时，获准使用的上下文会发送给模型服务，因此 AI 功能并不等于完全离线。这个 HTML 说明页本身不调用模型、不发送项目资料。

08 / 扩展与边界

外部连接能访问什么，由授权决定

CLI 是终端里的命令行工具；MCP 是让其他 AI 客户端发现并调用这些工具的接口。它们让外部助手也能使用 Project Mind 的资料和保存能力。

CLI/MCP 的 38 个已注册工具方法（24 读、14 写）通过同一 Rust 服务工作。连接凭据交给操作系统凭据机制管理；工具要先有范围与能力授权，普通读取不会顺手启动付费模型维护。外部 CLI 只调用数据工具，不自动启动模型；应用未打开时连接不可用。用户可以自行在 MCP 客户端配置模型，但这不等于本应用托管外部运行时。新建连接现已默认选择整个 Workspace，也能选一个 Project；两种范围都能选只读或协作。Workspace 范围包括直属内容和未归档 Project，新建 Project 随范围纳入。旧连接不会自动扩权。前端与新旧权限 Rust 定向检查已通过，真实连接和目标平台验收仍待完成。

新建连接入口已移除“最多 50 个 Record/File”对象清单模式。旧对象连接被拒绝并提示重建，不能直接变成整个 Workspace 的权限；协作模式保留 Record/File 历史恢复，并在设置中说明。内置助手在已启用范围内会自动获得读取会话依据所需的 session.read；外部连接仍按保存的权限检查。模型正文、提示词或工作目录都不能扩大连接授权。

Workspace 授权有两条入口。外部连接按持久授权范围调用工具；内置 Workspace 助手按每轮冻结的活动项目集合工作，外部连接不会因此自动扩权。跨 Project 分层概览已有 S6 本地定向证据，但尚未完成真实模型与目标平台验收；Workspace 长期记忆的 S7 本地实现与检查已完成，产品验收尚未完成。应用托管 Pi CLI / Claude Code 与任务菜单是 M3；GUI 关闭后继续维护的独立后台 Host 是 M4。这两部分已按用户决定暂缓。当前随应用运行的 Host 不能冒充 M4。

会话展示复用的 Pi Web UI 源码固定在 0.75.3，只负责消息呈现；实际模型运行时 SDK 是 0.99.1。两者版本不同是有意的职责拆分，不表示旧展示组件接管业务存储或模型凭据。

按需展开的小字典

Run、Profile、Provider 分别是什么？

Run 是会话里的一次任务；Profile 是应用中配置的模型及调用设置；Provider 是提供模型服务的外部供应方。

CAS、journal、JSONL 是什么？

CAS 是保存时比较“我读取的版本是否还是当前版本”，用于阻止旧稿覆盖人工新改；journal 记录 File 写入过程供故障恢复；JSONL 是逐行保存的会话原始记录格式。

Overview、QuickNote、MCP 是什么？

Overview 是 AI 从授权来源整理出的可追溯项目概览；QuickNote 是用户自己编辑的记事；MCP 是外部客户端调用本机工具的一种接口方式。
