理解 AI 增强：
能做什么，怎样实现

从一次提问讲起，看助手怎样找资料、记住讨论、保存成果，以及怎样把修改撤回。已实现的能力和还没完成的部分，都会分开说明。

代码基线 0b44e2d可离线阅读示意交互不连接真实项目
先看清状态：主要功能的代码已经接通，但首期版本（M1）尚未完整验收。真实模型、Windows/macOS 安装和 HTML 交互预览仍有待完成的项目。本页按钮仅用于演示。
01 / 全貌

助手要帮你完成的三件事

先认识三个名字：工作区（Workspace）是一整套资料库，项目（Project）是其中一项工作的范围；笔记、待办和文件在代码中分别叫 Record、Todo、File。

当前内置助手围绕项目工作：回答“资料里说了什么”，找回“以前为什么这样决定”，并把这次讨论落实为可继续编辑、可找回、可撤销的成果。普通提问从小范围入口开始，证据不够才继续读取原文。

01 / 查资料

给答案，也给来处

从 Record、File 等已授权材料寻找依据；需要时读对应版本和局部正文。资料不完整就说明覆盖范围，不能把摘录当全文。

02 / 找旧讨论

找回决定的上下文

先检索会话目录和摘要，再回读相关原话。过去的建议、计划和用户明确决定要分清，不把“提过”说成“定了”。

03 / 留下成果

保存成真正的笔记、待办和文件

把认可的方案保存为 Record、Todo 或 File，返回可打开的成果，以及实际保存的操作记录。下一轮可以接着改同一对象，历史版本还在。

目前这条路线的底层服务和不少界面已存在；“可以调用”“用户在正式安装的应用中顺畅完成”是两个不同结论。下面逐项标出。

02 / 实际能力

现在有哪些，边界在哪里

状态指截至本基线可核对的接入程度；“已接通”仍可能缺真实模型或目标系统的产品验收。用下方按钮筛选条目。

资料问答 部分完成

可以检索项目中的笔记、文件、待办、记事和转写材料，再分段读取、附上来源。扫描 PDF 不等于可读取文字；真实 PDF、旧工作区及模型回答的引用准确性仍需验收。

会话与历史 部分完成

Pi 会话原文、列表、搜索、恢复、停止结算和界面展示已有。使用真实模型续聊、强制退出后恢复、长消息显示等仍要在目标系统验证；按会话选择不同模型的后端支持已有，界面入口还缺。

笔记：创建与局部修改 已接通

创建笔记，替换、追加或删除指定正文块；保存前检查是否被人改过，保存后留下版本。可查看历史、恢复旧内容或撤回新建笔记。与原来的笔记编辑服务共用同一套保存规则。

待办：把明确行动落下来 已接通

创建待办，修改内容、期限、状态和子行动，保留修改前后的快照。撤销会检查有无后续修改。模型能否始终分清讨论与行动、避免编造日期，仍需真实任务验收。

文件：生成、续改与恢复 已接通

新建文件，精确修改文本或替换内容；继续修改保持同一个文件身份，成功修改形成新版本。支持查看旧版、文本比较、恢复和撤回新建文件。真实 Linux 命令行链路已有验证。

Project Overview 与知识 部分完成

独立的 AI 概览、来源证明、纠正、排除、预算与维护服务已有。首次启用的本地时区默认值、可见的频率/时区设置、真实日周期与覆盖质量仍待补齐。

CLI / MCP 外部连接 已接通

注册了 38 个工具方法（24 读、14 写），走本机 bridge 与同一业务服务；这不是 38 种独立产品功能。Linux 实际链路已验，macOS/Windows 安装、凭据与外部 Agent 使用仍待验。

HTML 成果 部分完成

HTML 作为 File 的源码、历史版本、续改和恢复已接通。应用内可执行、隔离的交互预览仍未交付；当前产品提示“交互预览暂不可用”，脚本错误与资源依赖诊断也待补。

Workspace 助手与长期记忆 后续规划

跨 Project 的分层 Overview、长期条目查看/纠正和 Workspace 助手属于 M2。现有外部连接可授权 Workspace 范围，不能据此说这些体验已经存在。

托管外部运行时与独立 Host 后续规划

应用托管 Pi CLI、Claude Code 与任务菜单属于 M3；关闭 GUI 后继续维护的独立 WorkspaceHost 属于 M4。

03 / 一项请求

从一句话到实际保存的成果

例如：“根据会议纪要更新发布计划，再创建三项待办。”下面这条执行链已接入代码，仍需用真实模型和正式安装包走完整个任务。

  1. 找依据
    查会议纪要，读当前计划；先知道要改什么。
  2. 说清方案
    说明准备更新哪份计划、增加哪些行动，细节按需展开。
  3. 确认一次
    同一方案只决定一次，不要求你逐段、逐工具审批。
  4. 保存成果
    应用检查版本后逐项保存，告诉你哪些成功、哪些失败。
  5. 继续或撤销
    打开真实笔记和待办接着改，也可以恢复任务前的内容。

模型提出修改方案，应用自己的保存服务负责真正写入。只有保存成功的操作记录才算完成。模型说“已经修改”本身不算凭据；中途失败也不能把已经保存的部分说成没发生。

只读

可以找资料、分析和回答，不允许创建或修改成果。

默认：确认后执行

先给简短方案，你确认后执行。补充修改要求会让旧方案失效。

主动选择自动执行

你启用这个模式后，助手在已有权限内直接保存；版本和冲突检查仍保留。

当前还不顺的一处：“确认”“确认执行”“同意执行”“执行吧”可以走确认路径，但“同意”“好的”会被当作新消息。按钮可以确认，这些常见短回复还需要补齐。带有“先改日期”等要求的回复，仍应先调整方案。
04 / 会话管理

一段对话，可以连续完成多次任务

你可以在同一段会话中先问资料，再讨论方案，最后修改成果。每次发起任务，系统会记录一次执行过程，代码里称它为 Run。一次会话包含多次任务，一次任务又可以产出多份笔记、待办或文件。

工作区
整套资料库›当前项目
助手工作的范围›会话
围绕一件事持续讨论›一次任务
一轮执行及其成果

原话保存一份，搜索另外建目录

Pi 把对话逐行保存为 JSONL 文件，这是原文。SQLite 数据库保存会话列表和搜索索引，方便快速找到相关消息。搜索到线索后，再读对应原文；不会把一小段搜索摘录当成全部语境。

收起、停止和继续各有含义

收起面板会保留草稿和阅读位置，不会自动停止任务。运行中可以继续写草稿；要发送新消息，先停止，等正在保存的操作处理完再发送。重开会话可以继续，已经保存的成果不能重复写一次。

历史列表和搜索让你回到以前的讨论。历史树中的旧分支也能进入索引，但当前不能据此宣称已有“任意消息分叉编辑”的界面。模型为长对话压缩上下文，也不能代替下节的历史检索和记忆。

当前项目的助手按当前项目读取资料；翻看历史或切换业务页面不会自动扩大授权。强制退出后恢复、网络故障后续聊等已有相关实现，真实模型与目标系统下的完整体验仍待验收。

05 / 记忆如何形成

需要多少依据，就往下读多少

新会话不会把整个 Project 塞给模型。助手先看到有限目录，查到相关主题再取概览或分段摘要；没有摘要时也可以直接搜索原文；若问题是“上次原话是什么”，就定位并读取相关消息。证据足够就停止读取，来源失效或只读了摘录就如实说明。没有搜到摘要也不能断言“从未讨论过”。

例子：问“为什么暂缓权限管理”，读取路线可能是：决定入口 → 相关会话摘要 → 作决定前后的几条原始消息 → 带来源的回答。它不要求通读全部聊天记录。

用户 QuickNote 与 AI Overview 分开。QuickNote 是用户自己的临时记事，沿原有编辑保存；Overview 是独立的 AI 派生概览，不改写用户原文。历史索引只是“找得到消息”的目录，也不是总结。会话摘要会区分计划、建议、明确决定、用户报告和实际保存成功的操作，并附可追溯来源。

资料变化和新消息会进入待整理队列，维护服务分批处理，并记录做到哪里；取消、失败或额度用完时，保留已有结果和进度，之后可以继续。

目前每批摘要只处理一条消息或一段长消息；每个项目每天最多 5 次摘要调用（按 UTC 日计数，失败尝试也计入），正常多轮对话容易积压。读取接口的单次 50 条消息 / 12000 字符上限为后续“同会话、同分支、同授权”的有界成段整理提供边界，不能误说现已合并处理。模型失败或额度用完时，原文搜索仍可用。

AI 排除、删除和授权缩小会过滤搜索、原文读取和派生结论；不能只藏来源链接却继续露出由它推得的结论。用户在应用界面查看自己的原始历史另有规则。已经发给外部模型提供方的内容无法追溯撤回。

人工在助手读完后又改了同一对象，旧基线不能静默盖掉新内容；需要提示冲突、核对目标。一次任务里同一个对象连续改几次，成组撤销以任务开始前的版本为恢复目标，每个对象分别恢复；如果部分失败，就分别显示结果，不会假装所有更改都已撤回。新建对象撤回后保留身份和历史，后续仍可恢复。

Record 有正文版本和块差异；File 保存真实字节版本，HTML 的 JS/CSS 也在其中；Todo 则以状态、期限、子项等修订快照处理，不能把它当作 File 的字节版本。三者都通过应用原有的保存服务，记录实际执行结果，而不是只靠助手一句“已完成”。

08 / 扩展与边界

外部连接能访问什么，由授权决定

CLI 是终端里的命令行工具；MCP 是让其他 AI 客户端发现并调用这些工具的接口。它们让外部助手也能使用 Project Mind 的资料和保存能力。

CLI/MCP 的 38 个已注册工具方法（24 读、14 写）通过同一 Rust 服务工作。连接凭据交给操作系统凭据机制管理；工具要先有范围与能力授权，普通读取不会顺手启动付费模型维护。外部 CLI 只调用数据工具，不自动启动模型；应用未打开时连接不可用。用户可以自行在 MCP 客户端配置模型，但这不等于本应用托管外部运行时。新建连接默认推荐 Workspace 协作：包括直属内容与未归档 Project，新建 Project 随范围纳入；也可选单 Project、只读或自定义。旧连接不会自动扩权。

自定义连接可只指定最多 50 个 Record/File；这种授权不包含创建、Todo 或会话历史。读取历史还要单独给 session.read。指定对象模式也不能借混合了其他来源的范围级摘要绕过边界。模型正文、提示词或工作目录都不能扩大连接授权。

Workspace 范围不等于 Workspace 助手。外部连接现在可以按 Workspace 授权；跨 Project 分层概览、Workspace 级长期记忆及其查看/纠正/抑制仍是 M2。应用托管 Pi CLI / Claude Code 与任务菜单是 M3；GUI 关闭后继续维护的独立后台 Host 是 M4。当前随应用运行的 Host 不能冒充 M4。

会话展示复用的 Pi Web UI 源码固定在 0.75.3，只负责消息呈现；实际模型运行时 SDK 是 0.99.1。两者版本不同是有意的职责拆分，不表示旧展示组件接管业务存储或模型凭据。

09 / 缺口与下一步

接下来，先把日常使用做顺

让确认和方案说明更自然

让唯一待定方案下“同意”“好的”等简短明确回复与按钮共用同一次确认；含修改要求的回复仍生成新方案。确认卡对已有对象要说清目标和动作。

按本地时间整理资料

首次启用采用电脑的本地时区，让维护默认在当地 03:00；补 24/48 小时频率、本地时刻、时区的可见设置。现默认 UTC 03:00，上海用户对应当地 11:00，并非凌晨；应用未运行时不会准时执行。

一次整理一段讨论

把同会话、同分支、授权一致的多条短消息在现有限额内合为一批；复用来源证明、预算与一起保存，不靠提高每日五次额度掩盖积压。

让会话可以选择模型

后端已支持为会话指定模型配置，界面尚无选择/展示入口；选择后，界面显示、连接验证和实际执行要使用同一个模型。

补齐 HTML 预览，完成真实使用验收

完成隔离的脚本交互预览、响应式宽度与依赖/脚本错误诊断，再在 macOS 和 Windows 应用实际使用的浏览器组件（WebKit / WebView2）中验证。可用的真实模型配置、macOS arm64/x64、Windows x64 的无开发环境安装、性能测量和三个真实项目的使用任务都还要实际执行、记录结果。

这条顺序是当前优先级，不把 M2～M4 从承诺中删掉。现有 Linux 确定性测试和浏览器夹具可证明接入，不能替代真实模型服务 与目标平台的结果。

按需展开的小字典

Run、Profile、Provider 分别是什么？

Run 是会话里的一次任务；Profile 是应用中配置的模型及调用设置；Provider 是提供模型服务的外部供应方。

CAS、journal、JSONL 是什么？

CAS 是保存时比较“我读取的版本是否还是当前版本”，用于阻止旧稿覆盖人工新改；journal 记录 File 写入过程供故障恢复；JSONL 是逐行保存的会话原始记录格式。

Overview、QuickNote、MCP 是什么？

Overview 是 AI 从授权来源整理出的可追溯项目概览；QuickNote 是用户自己编辑的记事；MCP 是外部客户端调用本机工具的一种接口方式。
