# 录音优先、持久补转写与统一录音控制

实施 Issue：[#296](https://github.com/xuchen-cloud/project_mind/issues/296)。

关联：#94；依赖已完成的 #293 / PR #295（异步本地转写、增量 FSMN）。Windows 实机验收继续跟踪 #294。

## 交付行为

1. 保留异步转写和增量 VAD。积压时先暂停预览，优先最终转写；持续跟不上时关闭实时转写、保存未完成区间，显示“录音正常，文字稍后补齐”。自动降级不自动恢复，不覆盖上次手动偏好；单独持久保存降级状态，暂停继续、应用重启和新录音均不自行重新开启，只有用户主动打开才恢复。
2. 实时转写开关控制识别计算而非字幕可见性；记住手动选择。录音期间可随时开关，不能重启采集、改变会话/原始时间轴、丢音频、漏字或重复写入。关闭区间由后台补转写，重新开启优先新音频。旧推理结果不得穿越切换边界写入或恢复旧字幕。
3. 接通 SenseVoice 本地补转写，复用持久恢复任务、WAV 读取、任务认领、进度游标和重试。录音结束后优先执行；断点继续、幂等提交、防止迟到/过期任务覆盖，保护 Record 正文用户修改。无识别配置时仍是纯录音，不虚构可执行补转写。
4. 停止先结束采集并保存音频，不等待模型推理。剩余文字后台补齐；超时保留任务并管理尚未退出的推理，不能无限并发重试。进度和重试入口位于对应 Record 页面。
5. Activity 计算积压/辅助检测失败降级关闭自动静音暂停，停止向失效队列投递；原始录音持续。真实设备、采集时间轴和写盘故障继续告警并保护保存。
6. 仅保留外部浮窗。展开态提供实时转写图标按钮，与设置菜单和后台有效状态同步。自动降级显示关闭及原因。
7. 应用内移除浮动控制面板，改为录音状态横幅；跨页面存在，点击跳回实际正在录音的 Record（包括切换 Project 后）。停止并保存音频后移除横幅，不等待后台转写结束。
8. 在外部浮窗点击结束录音，成功停止采集并保存后唤起主窗口并定位到刚结束的 Record；主窗口隐藏、最小化或位于其他 Project 时仍准确定位。不得等待后台补转写，停止保存失败时不得误报成功跳转。

## 工作包

- P1：持久本地恢复与数据完整性。依赖现有音频持久化；交付本地恢复、游标/租约、幂等和异常恢复。
- P2：实时控制与录音隔离。依赖 P1；交付开关、降级、非阻塞停止及辅助检测隔离。
- P3：浮窗按钮、应用内横幅和记录页后台状态。依赖 P2 的权威状态与命令。

## 非目标

不更换 ASR/VAD 模型、不增加 OpenVINO/DirectML/MKL 后端、不以扩容队列替代背压、不修复独立 WeLink #267，不改变 Transcript 只读与 Record 正文保存契约。

## 验收与验证范围

- Mac：同一音频回放，正常路径前后文本/时间边界对照；开→关→开、快速点击、设置和浮窗交叉操作、推理进行时切换/停止、暂停继续和新会话隔离。
- 延迟推理 5–10 秒与持续过载：音频连续保存、预览先让路、最终降级、缺失区间持久并补齐，无静默丢任务、重复文字或旧字幕回流。
- 恢复：重启、断点、超时与晚到结果、租约失效、失败重试、补转写期间开始新录音；用户已编辑正文保持不变。
- 辅助队列满/关闭不会暂停正常原始录音；原始队列/设备/写盘故障仍失败可见。
- 前端：横幅导航正确、录音结束即隐藏、外部开关实际控制推理且与设置同步、后台任务进度/重试。
- 受影响 Rust voice/db 测试、前端 voice/App 相关测试、TypeScript 与前端构建、静默原生构建；主 agent 做 Standards/Spec 自查，不启动 review 子 agent。
- Windows 设计兼容 WASAPI 10ms/256 队列及 Core Ultra 7 165H；当前只在 Mac 验证，Windows 原生构建/设备/性能结果留在 #294，不以 Mac 模拟代替。
