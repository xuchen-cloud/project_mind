# Record/File 移动、拖入与 File Version 标记

对应 Issue：[#304](https://github.com/xuchen-cloud/project_mind/issues/304)。范围：G13、G14、G15。本文记录交付契约；实现与平台验收进度以 Issue 和本轮 `status/fileflows.json` 为准，不能由本文推断已完成。

## 范围与术语

- 仅在当前同一物理 Workspace 内移动：工作区根级 → Project、Project → 工作区根级、Project A → Project B。
- Record 包含正文、元数据、固定版本及其资源。Voice Record 也属于 Record；存在活跃 Recording Session 时不能移动，不能静默丢弃音轨或转写。
- File 的归属是 Workspace 或一个 Project；文件夹内路径与业务归属是两个维度。
- 不扩展跨物理 Workspace、批量移动、Record 历史名称、手动删除 File Version 或新的自动清理功能。
- Archived Project 仍可出现在搜索结果中并标明状态，但禁止选为目标，沿用现有原生写保护。

## G13：移动

### 交互

Record 和 File 的右键菜单提供“移动到…”。弹窗展示当前 Workspace 名称、工作区根级和各 Project，支持按名称搜索。当前归属有“当前位置”提示并不可选；搜索框与操作按钮固定，结果列表使用 `HomeSidebarList` 的动态边缘遮罩。

一次选择对应一次提交。提交中不允许重复触发或关闭弹窗；失败保留选择和错误，成功才关闭。Workspace 绑定与对象基线在启动操作时冻结，切换 Workspace 后旧响应不能更新新页面。

同名 Record 不合并。File 的目标文件名被占用时明确报错，保留源位置与内容，不覆盖或自动拼接猜测名称；用户可先改名再移动。

### 保存与权限

1. 完成该对象的编辑器捕获与保存屏障，包括 active cell、IME 和跨窗口注册的编辑器；未确认 AI 内容不进入持久化。
2. 获取屏障后的原生权威 revision/hash，校验源实际归属及目标在当前 Workspace 内、未归档。
3. 在短事务和现有原生锁协议内迁移；源和目标 owner 锁使用确定顺序，File lease 在 Workspace commit fence 前。不得在已有 fence 内做全局恢复或等待编辑器。
4. 原生写入成功回执和 source/target 变更日志后，更新列表、打开页及查询缓存；发生失败时保留原编辑现场和恢复证据。

### 已打开内容、未保存编辑与新引用

- 跨归属移动只处理被移动的那个 Record/File：它已在源项目内打开时，先捕获并保存它未保存的 Committed Content；未打开时不触发其他内容的保存。隐藏 Tab、双栏中也按对象身份定位该内容，不能调用整个 Project、Workspace 或所有窗口的全局 flush。其他内容页的草稿、保存失败不参与本次移动。保存屏障期间阻止该对象继续产生未捕获的新编辑，保存完成后再取得用于移动的原生基线。
- 任一实例保存失败、存在待确认 AI 内容或仍未完成的编辑捕获时，取消移动；保留源归属、打开页和编辑内容，显示失败原因。不能先移走对象再要求旧 owner 下的编辑器保存，也不能以“放弃修改”代替自动保存。
- 原生确认移动提交成功后，自动关闭原归属下该对象的所有内容 Tab/内容视图并清除持久布局中的旧定位；仅移除该 Record/File 的视图，项目窗口和其他内容继续保留。关闭使用屏障已确认的编辑状态，不再次向旧归属发起保存。移动失败不关闭，回执不确定时先按原请求查询/重放确认，不能先销毁编辑器。目标位置不自动打开内容。
- 其他窗口收到移动结果后同样清除旧视图、当前引用来源、编辑会话和旧对象缓存；刷新源/目标列表和引用候选。工作区切换后的旧事件不得关闭新工作区中数字 ID 相同的内容。
- 移走后，原 Project 的新引用候选不再包含该对象；已打开候选列表和移动前发出的搜索响应也必须失效。用户点击旧候选、粘贴旧定位、使用旧缓存或 AI 发起新引用时，原生都依据提交时的实际 owner 重新校验并拒绝越权引用，不能只靠前端隐藏。
- 新归属允许的引用仍正常创建：目标 Project 可以引用该对象，Workspace 按现有规则可引用 Workspace/Project 内容；从 Project 移到 Workspace 的对象不能被原 Project 新引用。单纯在同一 owner 内改变相对路径不改变引用权限。
- 已存在的引用保留历史文字和依据，打开时按新的实际归属鉴权；保留历史引用不授予在原 Project 新建引用的权限，也不能让无关正文编辑偷偷新增一个旧引用。

Tag 是作用域内分类，不能把旧 Tag ID 直接挂到新归属。迁移应按 label/color 找到或创建目标 Tag 并原子替换关联，保留源 Tag 定义。名称冲突沿用原生 Tag 规则，不能吞掉不兼容标签。

移动不能放宽 Internal Reference 权限。Project 正文仅可引用该 Project；移动前必须在目标作用域校验当前正文的引用。存在目标无权引用的内容时明确阻止，列出需要处理的引用；不静默裁剪正文或使用 GUI 身份跳过作用域检查。保留版本维持原始上下文，不改写不可变历史，也不把历史引用转化成新归属的授权。原有入站引用在移动后仍应指向同一逻辑对象，但读取按新的实际归属重新鉴权；不能保留旧 owner 授权。

### 身份与原生实现约束

File 保留 `documents.id`、所有 `document_versions.id`/版本号/hash 和历史路径。物理源和目标可能分属不同卷，因此采用已校验的 staging/commit/recovery，不假定 rename 跨卷成功。更新 owner、目录索引、working state 和变更日志必须是同一个可恢复操作。

Record 当前 Project 和 Workspace 的行分别在 `notes` / `workspace_notes`，数字 ID 可冲突，canonical key 也包含 owner；直接 UPDATE 或复制后删除会破坏历史与引用。集成时必须先确定并测试稳定逻辑身份/旧引用解析方案：保留版本 UUID、版本号、正文 hash 与历史资源；作用域变动使用可重放的迁移回执返回新定位；旧定位的读取必须经过当前实际 owner 鉴权。不能为了沿用数字 ID 覆盖目标已有 Record。此项是实现前的共享契约工作，不得以“文件相对路径移动已存在”代替。

## G14：整个文件区域拖入

### 状态机

| 状态 | 可见提示 | 松手结果 |
| --- | --- | --- |
| 内容区空白、非文件行 | 导入提示 | 新增 |
| 同一 File 行不足 750ms | 不显示更新提示 | 新增 |
| 同一 File 行至少 750ms，更新提示已提交到 UI | 更新此文件版本 | 更新该 File |
| 换行、离开、滚动、切换树/列表或 owner | 清除旧提示，重新计时 | 依据新的状态 |

提示在 UI 出现前，即使计时已到，也不能执行更新。drop 消费一次目标后立即清空；DOM 和原生重复事件不得重复提交。持续 over 同一行不重置；初次悬停捕获目标显示基线，后来的后台刷新不能静默换成新基线。

整个文件内容区域包含树/列表、空列表、滚动内容和其余空白；固定菜单和对话框不作为文件目标。DOM client 坐标和 Tauri 物理坐标需要统一为 CSS 像素，按窗口 `devicePixelRatio` 换算并命中同一元素；不能同时乘除两次。滚动或尺寸变化需要重新命中或清除悬停，不能更新已移走的行。

### 单行更新

仅接受一个本地文件。多文件到已出现更新提示的单行时明确拒绝，提示“更新版本一次只能选择一个文件”；保持所有源不变。格式不兼容时拒绝并提示可拖到空白新增。格式比较使用规范化扩展名；同一格式大小写兼容，`.jpg/.jpeg`、`.tif/.tiff`、`.md/.markdown` 等同义扩展可视为同格式。缺少扩展名不能猜测二进制兼容性；由原生最终格式验证裁决。

更新沿用现有 prepare/commit 与 noChange 契约：目标显示基线经过保存屏障再确认；外部修改不能由拖入静默覆盖。不同源文件名不改目标名称、File ID 或历史。相同内容不新建空版本，回执为 noChange。

### 默认剪切与唯一原件保护

新增和更新均先导入/提交，确认目标持久化且内容 hash 可读匹配，再尝试清理源。成功清理使用系统回收站。源清理不是目标事务的一部分；失败返回单独警告，保留成功成果，不能回滚删除目标。

源清理由原生执行，不能让前端传一个任意路径就删除：绑定导入请求、源规范路径/物理身份/hash 与目标回执。清理前再次校验源未被替换、目标仍持有已确认内容；任一不匹配时保留源并报告。源与目标为同一物理文件、源在 Workspace 受管理目录/历史/资源中、符号链接或目录时拒绝清理。跨卷导入采用 copy-verify-commit，再回收原件。

目标失败不清理源；noChange 仅在目标内容可用并通过上述检查时允许回收独立外部副本。部分多文件导入逐文件记录成功与清理结果，不能因另一个文件失败隐藏已成功导入项。重试不重复导入/回收；Workspace 切换或跨窗口处理仍使用最初冻结绑定。

## G15：版本名称与重要标记

File Version 的 `name` 是物理文件名；新名称存为独立 `displayName`（空白归一为 null，最多 200 个 Unicode 字符，不接受控制字符），`isImportant` 默认 false。显示为 `V2（根据评审意见修改）`，无名称为 `V2`，版本号始终可见；重要状态另有星标及可读标签。

原生更新以 File、版本 ID、metadata revision 和 Workspace binding 为基线，校验版本归属，幂等提交名称/标记与日志。版本 ID/版本号/hash、创建时间和物理名称不变。File 改名、目录改名、跨归属移动、新版本创建都不能覆盖旧标记。

当前内核没有自动删除 File Version 的保留策略，也没有单版本手动删除入口；工作版本归档只追加快照。新增重要保护必须在原生持久化层约束所有自动清理候选和内容替换，不能只画星标。未来任何清理策略必须调用同一保护入口。取消重要标记后回归普通规则；不因此立即删版本。删除整个 File 仍走现有显式删除确认与可恢复回收流程；本需求不把重要版本扩展成禁止用户删除整个 File。

## 测试与证据

公共测试边界：可搜索目标弹窗；拖入状态 hook 与可见提示/消费；拖入操作策略及 IPC；File/Record 原生业务服务（真实临时 DB、文件与锁）；编辑器保存屏障；隔离 GUI。

- 移动：三方向、数字 ID 冲突、Tag 映射、合法/不合法引用、Voice 活跃/完成、保存失败、同名、重复请求、跨窗口、Workspace generation 改变、DB/磁盘故障和恢复。
- 打开状态：被移动对象的干净/dirty、Record/Markdown/Office、active cell/IME、隐藏 Tab/双栏；只保存该对象，其他页保存失败不影响移动且草稿保留；该对象保存失败则不移动不关闭，移动失败保留视图，保存成功后移动再关闭旧视图，移动中新增编辑受屏障约束，重开应用不恢复旧归属 Tab。
- 新引用：移动前已打开 picker/请求在途/候选已选中、粘贴旧定位、AI 和直接原生调用；移动提交后旧 Project 的新引用一律按实际归属拒绝，目标 Project/允许的 Workspace 可正常引用，现有历史引用与无关正文编辑不丢失、不扩大授权。
- 拖入：749/750ms、提示提交前消费、换行/离开/滚动/重挂载、树/列表空白、坐标缩放、重复事件、多文件/不兼容、noChange、源替换、同物理文件/受管理源、跨卷、目标失败、清理失败和部分成功。
- 版本：名称编辑/清空/Unicode 上限、metadata CAS、重开/改名/移动后读取、重要版本在所有原生保留入口和容量边界仍可读恢复、取消标记、不可变内容与身份。

所有重型构建、Rust、安装和 GUI 使用本轮 build lock；Rust 关闭增量并复用可再生成 target；针对性 Vitest 单 worker。GUI 验收前告知并使用隔离 fixture，避免 Tauri 自动监听。

Windows 物理坐标、缩放与回收站需要真实 Windows Tauri 窗口和隔离目录证据；mock/macOS 不替代。缺少此环境时记具体阻塞，不宣布本 Issue 完整交付或关闭。
