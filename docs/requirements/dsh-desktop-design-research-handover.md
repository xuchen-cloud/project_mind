## 1. 接收后如何推进

1. 阅读本文 §2–§3，区分已经实操的行为、仅看见的入口和产品建议；需要补充交互证据时执行 §5。
2. 检查当前分支和工作树，读取[内容 Tab 实施交接](project-content-tabs-handover.md)与[执行记录](project-content-tabs-execution.md)，确认既有能力和未完成验收。本文源码定位基于 `1e0ee49`；后续以实际代码为准。
3. 优先选 D1 或 D2，写清关联 Issue、依赖、文件范围、交付行为、非目标、验收及受影响测试。候选涉及新增产品行为时，先把采用值写入对应规格。
4. 按 §4 复用现有能力完成真实页面接入，再集中进行 GUI 验收。修改源码前检查 `tauri dev` 自动重启进程，避免打断用户工作。
5. 交付时记录源码基线、改动、逐项验收证据、验证复用依据、Standards / Spec 自查和剩余解锁条件。Review 子 agent 仍需用户明确同意；实施子 agent 按仓库授权使用 `gpt-6.1-sol`。

**本交接完成条件：** 接收者能复述实际调研范围，并可从任一候选包直接确定输入、复用入口、交付行为和验收；候选实现状态与既有修复状态分别明确。

## 2. 实际调研方式与范围

### 环境和证据来源

用户要求查看电脑上已打开的 DeepSeek Harness Desktop，实际窗口为 **DSH Desktop**。通过 Computer Use 获取真实 macOS 窗口截图和无障碍树，结合实际菜单操作观察交互，再与 ProjectMind 本轮真实内容双栏页比较。

- 应用位置：`/Applications/DSH Desktop.app`，应用标识 `io.dsh.desktop`。本次记录没有核验其安装版本。
- 证据为会话内截图、无障碍树和操作结果；没有可核验的独立截图归档，本文不提供虚构附件路径。
- 观察聚焦文件 Tab、阅读工具栏、预览方式入口、布局入口和会话输入区；未记录用户文档正文、编辑用户文件或向 DSH 模型发送请求。
- 仓库引入的 DSH 源码固定在 `dsh-v0.2.0-rc.2`，见[provenance](../../packages/dsh-ui/provenance.json)。它是代码来源依据，不能据此断言现场安装程序的版本相同。

### 实际执行路径

| 步骤 | 实际操作 | 获得的证据 |
| --- | --- | --- |
| 1 | 读取已打开 DSH 窗口截图与无障碍树 | 文件 Tab、工具栏、布局按钮及会话输入区域的可见结构 |
| 2 | 观察文件阅读页，并与 ProjectMind 实际双栏页比较 | 工具密度、文件类型与会话入口的局部差异 |
| 3 | 展开文件的“打开方式”菜单 | 菜单包含 Markdown、代码、纯文本三项 |
| 4 | 将同一 Markdown 文件切换为代码显示 | 确认该文件的阅读方式可以切换到代码 |
| 5 | 恢复原 Markdown 阅读方式 | 确认本次切换可以恢复 |

本次只确认上述阅读方式切换。菜单中的纯文本选项没有实际切换验证；外部编辑器、分栏、全屏、收起右栏和快捷键没有完成操作链。没有测试布局重启恢复、跨项目后台运行、模型切换或完整可访问性，也没有性能测量或用户访谈。

## 3. 观察结果与产品判断

| 主题 | DSH 实际观察 | ProjectMind 对照与建议 | 证据等级 |
| --- | --- | --- | --- |
| 文件工具栏 | 路径、查看方式、刷新和外部打开集中在一条工具栏 | 我们本轮文件位置、引用到会话、版本操作占三行，压缩常驻区域可增加双栏阅读空间；固定版本语义需继续可见 | 界面观察；收益为设计判断，未量化 |
| 阅读方式 | Markdown / 代码 / 纯文本菜单；同一 Markdown 文件切代码后恢复成功 | 沿用已有预览与源码能力，整理可发现的查看入口；可用方式随现有格式能力提供 | 菜单观察 + Markdown/代码实操 |
| Tab 辨识 | 文件 Tab 带类型图标 | 混合 File / Record / Session Tab 需增强类型与后台运行状态辨识 | 界面观察；未验证 DSH 后台状态行为 |
| 布局入口 | 可见分栏、全屏、收起右栏入口 | 可考虑暂时放大聚焦栏，并保留原双栏布局以便恢复 | 仅入口观察；恢复策略是本产品建议 |
| 会话输入区 | 可见当前模型、访问模式及命令/文件提示 | 会话内展示实际使用的模型和设置入口，复用统一 AI 配置 | 界面观察；未验证模型或访问模式切换 |

局部启发式严重度采用 0–4（0 无问题，4 无法完成任务）：ProjectMind 阅读工具密度为 2，Tab 类型/运行状态辨识为 2，模型入口发现为 1。这些是本次局部判断，不是全产品评分。对新用户的入口发现、熟练用户的阅读效率影响尚需产品验收确认；没有完成键盘或辅助技术用户研究。

**建议顺序：** 先减少 File 工具栏占用并改善 Tab 辨识，再接入会话模型入口和临时阅读专注。采用 DSH 的呈现启发时，继续以 ProjectMind 的项目身份、版本引用和运行时绑定为行为依据。

## 4. 候选实施工作包

所有包保留 #124 已有约束：同一对象只有一个 Tab，File 版本属于查看状态，布局属于 Project，跨项目任务可在后台并行。滚动列表遵循[滚动区域与边缘遮罩规范](../design-system.md#滚动区域与边缘遮罩默认规范)；状态切换保持连续位移/缩放过渡并支持 reduced-motion。

### D1 · P1：压缩 File 常驻工具栏

- **依赖与输入：** 已有 File 页面、版本/来源能力和位置操作；覆盖最新版本、固定历史版本、位置未确认及不支持预览状态。
- **交付行为：** 将文件名、版本状态、查看/刷新等主要阅读动作组织为紧凑工具栏；固定版本与历史警告始终可见。位置改名/移动与目标 Session 选择通过现有弹出层按需展开。
- **复用入口：** [ProjectFileContent](../../src/components/document/ProjectFileContent.tsx)、[ProjectFileIdentityActions](../../src/components/document/ProjectFileIdentityActions.tsx)、[ProjectFileSessionReference](../../src/components/document/ProjectFileSessionReference.tsx)及其现有测试。继续调用原生身份、版本和来源服务。
- **非目标：** 新增格式渲染器、改动 File 身份/CAS、隐藏历史警告或重写引用流程。
- **验收：** 同一窗口和内容下记录改前/改后常驻高度，双栏阅读可用高度增加；窄窗动作可到达；固定 v1 刷新后仍读 v1；引用仍携带 v1；改名/移动仍定位原 File；失败状态明确；键盘可打开并退出所有新增浮层。
- **验证范围：** File 页、位置操作、Session 引用的受影响用例；macOS 实际最新/历史页、双栏和窄窗。只有接口/数据语义改变时补对应原生验证。

### D2 · P1：Tab 类型、标题与后台运行状态

- **依赖与输入：** 统一内容布局及 Project 独立运行时；混合 File / Record / Session Tab、长标题和项目 A/B 并行运行场景。
- **交付行为：** Tab 展示对象类型，File 可区分已有格式；长标题截断后可发现全名。Session 后台运行状态可发现，状态属于实际目标 Session，停止动作只作用于该 Session。
- **复用入口：** [ProjectContentLayoutView](../../src/components/project/ProjectContentLayoutView.tsx)、[ProjectContentWorkspace](../../src/components/project/ProjectContentWorkspace.tsx)、[内容布局模型](../../src/lib/project-content-layout.ts)、[内容 store](../../src/state/project-content-store.ts)、[运行 store](../../src/state/agent-panel-store.ts)、[Host 事件绑定](../../src/lib/dsh-host-events.ts)。先确认现有事件中的 Session 身份；Project 级 busy 信号不能直接当作该项目所有 Session 都在运行。
- **非目标：** 新建运行时、引入另一份布局权威、以名称/路径/版本改变 Tab 唯一性。
- **验收：** 三类 Tab 和长标题可辨识；左右栏移动、历史引用和重复打开保持同一 Tab；运行中切换内容/Project 后状态准确；停止 B 不停止 A；运行结束后状态更新；横向溢出遮罩随滚动及尺寸变化正确显示。
- **验证范围：** 布局展示、运行状态映射及事件相关用例；实际双栏混合 Tab 和受控 Provider 的 A/B 并行场景。

### D3 · P2：会话内模型信息与设置入口

- **依赖与输入：** 当前统一 AI 设置、默认绑定、会话启动绑定与配置错误状态。开始前核对正在进行的设置工作，明确其真实共享接口。
- **交付行为：** 输入区展示当前模型并提供设置入口；运行中展示本次任务实际绑定模型，配置缺失时提供明确可操作入口。
- **复用入口：** [ProjectSessionContent](../../src/components/agent/ProjectSessionContent.tsx)已有设置订阅与 `onSettings`、[DSH client adapter](../../packages/dsh-ui/adapters/client.jsx)及现行共享 AI 设置服务。复用现有设置入口和配置状态，接收新的共享接口时按其契约适配。
- **非目标：** 新建独立模型配置、复制密钥状态、从界面暗中更换运行中任务的模型或访问授权。
- **验收：** 配置缺失可进入正确设置页；空闲会话显示实际当前绑定；启动任务后修改默认配置，运行提示仍对应本次任务；后续任务使用新绑定；切换项目后提示与实际任务一致。
- **验证范围：** 设置入口与绑定展示的受影响组件用例；受控 Provider 的实际启动/配置变更验证。DSH 现场模型切换没有证据可直接替代此验收。

### D4 · P2：临时放大当前阅读栏

- **依赖与输入：** 已有双栏布局、聚焦栏、页面可见性与窄窗降为单栏的模型；需要先确定临时状态的存续范围。
- **交付行为：** 提供放大当前栏与恢复入口；恢复时保留原栏成员、比例、选中 Tab、草稿和查看状态，过渡连续并遵循 reduced-motion。
- **复用入口：** [ProjectContentLayoutView](../../src/components/project/ProjectContentLayoutView.tsx)、[ProjectContentWorkspace](../../src/components/project/ProjectContentWorkspace.tsx)、[内容 store](../../src/state/project-content-store.ts)、[布局样式](../../src/components/project/project-content.css)。复用现有可见性/聚焦控制与编辑器保存协调。
- **非目标：** 第三栏、复制页面、借临时放大改写持久双栏描述或重做操作系统全屏。
- **验收：** File/Record/Session 均能放大再恢复；原比例与草稿保留；放大期间后台任务继续；窄窗切另一栏与放大状态不冲突；键盘可恢复；普通及 reduced-motion 模式下状态变化可理解。
- **验证范围：** 布局展示、可见性、关闭/保存协调的受影响用例；真实双栏含未保存 Record 和运行 Session 的放大/恢复链。

### 并行与整合

D1 的 File 组件范围可与 D2 的 Tab 展示并行。D2 与 D4 共享布局文件，顺序实施或先由主 agent 划定修改边界；D3 等共享设置接口稳定后接入。各 agent 只执行其包的针对性验证，由主 agent 集中整合与验收，复用仍有效的已通过结果。
