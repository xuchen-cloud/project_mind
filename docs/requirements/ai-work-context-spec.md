# AI 工作上下文：统一产品规格

更新：2026-10-10。状态：**本轮目标已确认，待补实现与产品验收**。本规格统一此前讨论和历史需求包；不以文档整理宣告功能完成。实现基线为 `cc3ecf9`，实际证据与缺口见[验收台账](ai-work-context-acceptance.md)。父需求继续使用 [#97](https://github.com/xuchen-cloud/project_mind/issues/97)。

## Problem Statement

用户的工作材料、行动和决定分散在文件、记录、待办与会话中。每次向 AI 提问都重新解释背景很费力；保存了方案，也不意味着已经采用方案。助手需要分清真实决定、临时讨论、自己的建议和已经完成的操作，才能可靠地继续工作。

现有系统已经具备项目与 Workspace 会话、知识维护、来源、版本和操作收据，但产品概念和规划存在重叠：编辑器 Skill、Overview、长期记忆、会话摘要及不同实施批次混在一起。长期记忆还不能在会话中即时管理，通用偏好不能自然沿用于项目，记忆判断规则也不能由用户或获授权的 Agent 调整。历史包中“后续目标”和“本地实现”需要与当前要求、产品验收分开。

## Solution

### Context 与 Agent

产品以 **Context 和 Agent** 为两大部分。Context 包含 File、Record、Todo、会话、知识、Overview 和记忆：它既是 Agent 的上下文和成果沉淀，也是人机共同查看、修改和继续工作的页面。各对象继续保持自己的业务身份、归属、版本及来源规则。

Agent 在这些内容中理解目标并行动。Project Mind 使用基于 Pi SDK 的内置 Harness，负责模型调用、会话、工具和组件接入；底层 Context 能力独立于 Harness，经界面、内置调用及既有 Mind CLI/MCP 复用。编辑器是协作场景之一，既有 AI Editor Skill 不再作为整个 AI 产品的分类中心。

### 记忆行为与整理行为

Memory 广义包括 Overview 和长期记忆。**记忆行为**处理交互中的新信息及明确目标更新；**整理行为**回看已有资料与理解，处理合并、矛盾、过时和结构调整。两种行为均可操作 Overview 或长期记忆，不按产物建立两套行为系统。

长期记忆唯一归 Workspace；项目稳定背景与约定进入 Project Overview 的专门栏目。项目 Agent 可沿用当前授权可用的 Workspace 记忆，却不因此获得其他范围的原始资料或任意写入权限。用户在项目会话明确要求保存通用偏好时，保存到 Workspace 并告知；项目专属内容留在项目。

用户明确要求记住、纠正、替换或遗忘时，在当前交互中处理；用户明确做出决定时，可以即时更新 Overview 的小范围有类型增量。普通讨论和新建文件、记录先登记待处理来源，随后由整理判断，不能仅因保存了方案就标为已采用。Project 即时增量只标记 Workspace 下游待核对，整理再合并处理。

记忆与整理的判断规则写在**一个 Workspace 统一 Skill 文件的两节**中。用户及有相应文件修改权限的 Agent 直接修改并告知结果，下一次模型调用采用新版本，包括同一任务的后续调用。整理开关、时间和频率由 Harness 的结构化工具或脚本实际保存；只修改 Skill 中的时间文字不能声称调度已改变。行为文件与运行设置分别保存，保留成功项，失败项单独重试。

### 工作与交互

打开空会话不预读项目正文，也不调用模型。实际提问从小的知识入口及符合预算的有效记忆快照开始，按问题逐步读取相关知识、摘要、局部原文或指定完整对象。引用可定位实际来源；来源过时、覆盖不足和预算不足均如实说明。

助手在稳定的非模态面板中协作，可展开到主工作区；草稿、阅读位置、待定方案和操作结果随会话保存。普通业务成果默认一次任务审阅后执行，用户也可选协作或只读。成果链接到真实 Record、Todo 或 File，可继续修改、查看版本和撤销，失败不能被聊天结束掩盖。知识状态和维护入口按需打开，不在项目首页新增“继续工作”卡片。

## User Stories

1. 作为项目用户，我希望直接询问现有材料和决定，以便不必每次重新介绍项目。
2. 作为用户，我希望文件、记录、待办和会话既可被 Agent 使用也可供我编辑，以便在同一个工作现场协作。
3. 作为编辑器用户，我希望选区或图片能明确当前处理对象，以便 Agent 围绕目标读取已授权的相关内容。
4. 作为项目用户，我希望项目背景与约定独立于临时 QuickNote，以便整理不会覆盖随手记录。
5. 作为 Workspace 用户，我希望结合授权项目与直属内容提问，以便了解跨项目进展而不暴露未授权项目。
6. 作为用户，我希望新会话只从小的入口开始，以便减少等待和重复模型成本。
7. 作为用户，我希望 Agent 按问题展开摘要或原文，以便既能概括方向也能核对精确措辞。
8. 作为用户，我希望引用定位到实际对象、版本或消息，以便检验依据。
9. 作为用户，我希望来源过时、未命中或读取不完整时得到说明，以便不把旧摘要或局部读取当作全部事实。
10. 作为用户，我希望较早的讨论可被检索并有限回读，以便继续过去的工作而不加载全部历史。
11. 作为用户，我希望模型建议、用户计划、明确决定及操作结果保留不同状态，以便未执行建议不会成为既定事实。
12. 作为用户，我希望明确要求记住的通用偏好立即保存，以便下一次模型调用就能使用。
13. 作为项目用户，我希望通用偏好保存到 Workspace、项目约定留在项目，并获知位置，以便避免重复保存或错误归属。
14. 作为项目用户，我希望沿用获授权的 Workspace 记忆，以便不在每个项目重复说明通用偏好。
15. 作为用户，我希望明确而完整的记忆请求不重复询问确认，指代含糊时先澄清，以便保持协作流畅且不误写。
16. 作为用户，我希望点名纠正或替换记忆，以便后续任务采用最新事实并保留历史。
17. 作为用户，我希望要求不再记住某项内容后它退出有效输入，并保留停用约束，以便旧版本或整理不会随即带回它。
18. 作为用户，我希望撤回某一条停用决定时只影响该决定，以便其他限制继续有效。
19. 作为用户，我希望长方法和完整讨论保留为资料入口，以便记忆简洁而详细依据仍可查找。
20. 作为用户，我希望明确采用方案时即时更新对应 Overview 条目，以便当前理解及时反映决定。
21. 作为用户，我希望保存文件或普通讨论先登记来源而不自动标为决定，以便试探和草稿仍有正确语义。
22. 作为用户，我希望频繁项目更新合并成一次下游核对，以便减少不必要的 Workspace 模型调用。
23. 作为用户，我希望修改“什么值得记住、如何整理”的 Skill 并看到结果，以便调整 Agent 的工作方式。
24. 作为用户，我希望有权限的 Agent 按我的要求直接修改同一 Skill，以便自然语言调整可以落地。
25. 作为用户，我希望 Skill 在下一次模型调用生效，以便当前任务也能采用新行为而不打断正在进行的请求。
26. 作为用户，我希望所有项目沿用 Workspace 的统一行为配置，以便规则不会在项目间分叉。
27. 作为用户，我希望用自然语言调整整理时间、频率或开关并收到实际保存结果，以便调度真正改变。
28. 作为用户，我希望行为规则与调度同时修改时保留成功项并仅重试失败项，以便局部失败不撤销已完成调整。
29. 作为用户，我希望手动或按计划整理已有资料，以便去重、处理矛盾和过时信息。
30. 作为用户，我希望后台整理不覆盖我已确认或纠正的内容，以便保留决定权。
31. 作为用户，我希望整理遇到新会话更新时保留已结算进度并重新准备受影响内容，以便不丢工作也不覆盖新决定。
32. 作为用户，我希望无变化时不生成、无新知识时不强行写入，以便避免无意义成本和内容堆积。
33. 作为用户，我希望记忆容量不足时得到整理或按需读取的明确状态，以便不会静默遗漏偏好或无限重试。
34. 作为用户，我希望助手面板可收起、展开并保留输入和阅读位置，以便继续操作业务页面。
35. 作为用户，我希望消息、方案、过程与实际结果属于对应任务轮次，以便清楚知道每项工作的状态。
36. 作为用户，我希望默认审阅一个业务任务后执行，也能选择协作或只读，以便按工作需要控制写入。
37. 作为用户，我希望用方案后的真实回复确认、修改或取消，且按钮具有相同结果，以便不必使用固定确认口令。
38. 作为用户，我希望 Agent 创建或按稳定块修改 Record、创建或更新 Todo，以便讨论能形成可继续工作的成果。
39. 作为用户，我希望 File 生成和后续源码修改保留同一身份及版本，以便继续修改时不会新增同名文件或丢掉旧稿。
40. 作为用户，我希望人工修改后的旧基线提交被拒绝，以便 Agent 不覆盖后来的工作。
41. 作为用户，我希望保存成功有真实收据、部分失败逐项说明、重试不重复创建，以便信任完成状态。
42. 作为用户，我希望撤销或恢复成果时保留版本，并说明冲突，以便可逆地试用 Agent 输出。
43. 作为用户，我希望停止后保留草稿、等待已开始操作结算再发送，以便中断不会隐藏已完成写入。
44. 作为用户，我希望排除资料、撤权或删除来源后派生内容及时停止使用，以便旧摘要不绕过授权。
45. 作为外部工具用户，我希望 Mind CLI/MCP 使用与内置助手相同的作用域、版本和有界结果，以便安全接续工作。
46. 作为外部连接用户，我希望只读连接不能写、旧授权不能静默扩权，以便连接行为符合我的选择。
47. 作为桌面用户，我希望正式安装包自带必要运行资源并如实报告模型或连接故障，以便不依赖开发环境，普通工作仍可继续。
48. 作为维护者，我希望从一个当前规格与交付导航查到历史依据和真实验收缺口，以便旧包不再形成冲突执行路线。
49. 作为用户，我希望在 AI 设置选择系统代理、自定义 HTTP/HTTPS 或直连，并让同 Workspace 的模型请求共用，以便使用实际可用的网络连接。

## Implementation Decisions

1. **共享 Context 服务与 Harness 分层。** 底层保持实际归属、读写、检索、版本、授权、证据和收据；内置 Harness 的记忆组件组织读取、使用和维护。继续使用 Pi SDK 与随应用打包的 Node，复用已有会话和工具链，不提供不同 Harness 切换。
2. **Workspace 统一配置。** 新行为 Skill 与扩展配置统一在 Workspace，各项目沿用，不设项目独立启停或覆盖。已有模型 Profile、会话模型覆盖、scope 启用及执行模式保持各自含义；统一行为配置不自动取消这些边界。
3. **记忆归属和权威。** 长期条目唯一归 Workspace，Project Overview 增加可单独读写的“项目背景与约定”栏目。正文仍以已有 SQLite 知识及不可变版本为权威，长内容留在资料、知识节点和历史；不建立第二份 Markdown 记忆数据库。背景、领域、兴趣、方法、偏好、知识入口六类及确认/启停/来源状态继续保留。
4. **新结构初始化。** 本轮不做历史 AI 数据迁移、旧身份映射或兼容接入；按新结构初始化。此边界只针对尚未开展用户测试的 AI 派生数据，不删除或改变 Record、File、Todo、QuickNote、Transcript 等业务数据，不取消必要数据库结构升级与备份。
5. **读取与范围。** Project 读取 Workspace 记忆使用窄能力，不开放其他范围的原始内容，不授予写入。外部连接须显式获得相应能力，旧 grant 不扩权；Workspace 内容授权也不等于所有项目授权。排除、归档、删除、撤回、撤权后递归核验派生依据。
6. **请求绑定的记忆写入。** 内置项目会话中的明确通用记忆请求可取得绑定真实用户消息、具体目标和内容的单次 Workspace 写入授权。内容及范围明确则保存并告知，不再确认；不明确则澄清。只读拒绝写入。普通 Project grant、后台推断、引文与外部连接不能继承该授权；此规则不免除普通 Record/Todo/File 的任务审阅。
7. **可信确认与小增量。** 即时 Overview 更新仅由真实明确决定/命令或点名修订触发，绑定目标、来源、基线版本和原生消息/操作证明。模型自报“已确认”无效；保存方案的收据只证明保存。提交有类型的局部增量，保留其他条目，不能整份重写。
8. **原始保存与生成分开。** 来源保存后持久登记并合并 pending，无论是否生成即时知识。维护只处理变化；普通讨论、草稿和未采用建议不即时升级。即时增量不提前结算整理水位。来源索引与文件原始字节用途不同，提取文本不能代替源码修改基线。
9. **两种行为的原生护栏。** 会话沿 readOnly/review/collaborate 模式与上述具体授权规则；整理沿草稿、来源/权限复核、CAS 和原子发布。后台结构性替换、删除、减信息合并及修改已确认/纠正内容复用待审保护，不以无人回应或 Skill 文本取得授权。
10. **并发恢复与下游。** 会话增量导致整理基线变化时，旧草稿失效；保留已发布结果、已结算进度及未消费来源，从最新基线重准备受影响内容，重新验证仍可复用的证据。不得硬发布旧草稿、清空整个批次或热循环。Project 更新只标记 Workspace 依赖 pending，整理合并消费；依赖版本失效仍立即过滤。
11. **统一内容操作。** 支持新增、替换/纠正、合并、整理删除、用户遗忘/停用与重新启用，使用稳定目标、预期版本和幂等请求。合并保留完整来源并集与被替代关系，模型判断语义，不以字符串或同来源哈希代替理解。用户遗忘保留抑制，原始业务内容及历史不随记忆删除。
12. **抑制边界。** 原生规则限定同 scope、类别和原始来源，界面如实说明可能覆盖该来源中的其他同类候选；不宣称全库语义擦除。跨独立来源重现由模型结合停用约束处理并做真实模型验证；旧版本、旧 Run 证明和历史压缩内容不能恢复为有效输入。
13. **联合沉淀事务。** 一次整理的 Project Overview 与 Workspace Memory 结果在同一短事务中复核两侧版本、权限、来源、容量并共同发布；任何一侧失败，两侧不部分成功。可以两侧均零变更，不因无内容强行新增。
14. **Skill 与结构化设置。** 一个文件含记忆/整理两节；有权限直接修改、保留版本并报告实际结果，每次 Provider 请求加载最新有效版本，已发请求不重启。修改行为不自动重写旧内容。Harness 只对授权的运行设置提供结构化工具或脚本，不开放任意 scope 设置或 Context Instructions。行为文件与设置独立保存、仅重试失败项，与联合沉淀事务区别明确。
15. **精简快照与总预算。** 每次请求采用当前有效、获授权的完整精简记忆集合，并按需展开细节；不能任意取前八条冒充完整。普通知识导航默认不超过 2000 Unicode 字符；记忆预算另行明确，和系统指令、历史、工具、输出预留一起按实际模型上下文核算。默认容量需通过大小上下文模型的实际序列化边界验证并记录后才能交付；超额明确进入整理或按需读取，不静默截断。记忆正文标记为上下文数据，与可信系统指令分离。
16. **会话与历史职责。** Pi 原始会话及压缩负责续聊，已有索引/投影负责跨会话检索；额外摘要仅补必要知识，不固定每轮重复生成。保存真实消息、分支、Run 和来源身份；当前策略在再次读取及压缩恢复时复核。知识摘要不能洗掉原始依据或将失败任务写成经验。
17. **普通成果与审阅。** review 默认一次任务确认，模式在 Run 开始冻结；按钮与模型决定共用原生持久路径。模型确认只能绑定当前候选及方案后真实用户回复，修改使旧候选失效。Record 用稳定块及提交内容版本，File 复用同 ID/版本/hash 和原始字节，Todo 用修订及前后快照；各对象独立结算，跨对象任务不承诺全局原子。中断、重试、撤销和恢复保留真实结果及后续人工工作。
18. **交互与接入。** 会话面板非模态，保留草稿/阅读位置，消息、过程、方案和成果按轮次展示；错误可见，顶部保持业务信息简洁。复用现有 UI 标准和 Pi 展示组件的薄适配，不将 SDK 引入主包。首版同一会话不并发发送，停止结算后再发送。既有 CLI/MCP 复用服务，本机 MCP stdio；外部范围/模式显式选择，应用关闭时明确失败而不另开数据库。

## Testing Decisions

验收边界已由用户确认：**复用现有原生服务、打包 Pi 调用链与界面用户流程**，验证持久保存、下一次调用生效和并发恢复；真实模型与目标桌面设备另做产品验收。不为文档整理新建测试框架。

1. 以用户可观察的保存位置、有效内容、版本、实际收据、拒绝结果与恢复行为为断言，避免只测内部函数调用或复制实现细节。
2. 在共享服务与持久化接缝复用已有知识/Overview、来源、grant、CAS、幂等及抑制测试：核 Workspace 唯一归属、Project 栏目、读写隔离、旧来源失效、联合事务失败零写入、即时增量与整理冲突后不丢进度。既有测试仅作基础，不能证明新增行为已接线。
3. 经随包 Node/Pi 与既有 Host 测试实际调用原生工具，核真实消息/候选绑定、明确记忆请求无重复确认、行为文件与设置部分失败、同一 Run 下一次请求采用 Skill 和最新记忆、会话恢复与压缩过滤；使用模拟 Provider 时只声称调用链验证。
4. 复用真实组件与模拟 IPC 的界面流程，核修改规则、实际保存位置、知识状态、方案回复/按钮一致、部分失败与成果继续修改。截图和模拟 IPC 不作为目标平台原生交付证据。
5. 对完整精简快照序列化测量总输入，用大小上下文模型配置验证容量、工具结果、历史和输出预留共同受限，失败不能静默漏条。已有导航八卡片测试不能代替此项。
6. 真实 Provider 验证语义边界：临时问题不变偏好、草稿不变决定、同义重复合并、独立来源遗忘重现、明确决定增量及 review 真实回复判断。至少以真实项目任务记录来源、纠正次数和实际结果，避免以自动生成量衡量成功。
7. macOS arm64、macOS x64、Windows x64 的正式安装包与干净环境验证签名/安装、资源随包、CLI、原生存储/WebView、杀进程与恢复。Linux 容器、mock、单测或历史部分通过不能代替设备签收。
8. 保留 A01～A76、ML01～ML22 的编号和证据；按当前 V1～V5 对齐覆盖，旧 M/R/WP/S/LM 仅是追溯编号。本次纯文档改动检查 diff、链接、锚点及要求一致性，复用历史应用验证而不重复运行全量构建。

## Out of Scope

- 第一版不接入第三方 Skill/MCP/Plugin 的完整扩展客户端、可替换记忆组件、向量/图检索、经验自动孵化 Skill 或多 Agent 编排；分层保留接入位置，不能据此声称已有 Pi 资源发现开放。
- 不提供 Pi CLI、Claude Code 等外部 Harness 选择、外部运行时任务菜单，或关闭应用后的独立常驻服务。既有面向外部调用方的 Mind CLI/MCP 属于当前能力。
- 不迁移或兼容历史 AI 派生数据，不新增 Project Memory、Workspace File、收集箱项目、第二份记忆权威或新调度框架；不删除业务资料。
- HTML/Markdown/Word/Excel/PPT 的项目内预览、手工编辑、脚本隔离及格式组件集成归独立 #118/#115。AI 保留 File 生成、原始源码读取、同 ID 续改、版本、撤销和真实入口；字节保存不代表 Office 语义编辑能力。
- 不新增首页“继续工作”卡片，不开放 QuickNote、原始 Transcript、声音轨和只读纪要给本次 Agent 正文修改接口；既有编辑器未接受预览继续遵守 Committed Content。
- 不引入任意过期删除、关键词理解替代、固定每日模型调用配额、全局跨对象/文件系统原子事务或全库语义擦除承诺。
