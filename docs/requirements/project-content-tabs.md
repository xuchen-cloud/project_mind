# 项目内容 Tab、双栏与统一文件管理需求

更新：2026-10-13。状态：#124 实施中，本轮 macOS 复验、代码与待补平台验收见[执行记录](project-content-tabs-execution.md)；本文不代表完整功能已交付。

父 Issue：#124。所交付格式与平台验收分别记录，全部完成前保持 Issue 开放。

关联需求：[DSH 组件融入主应用](dsh-ui-component-integration.md)、[项目文件预览与编辑 / #118](project-file-integration.md)。领域术语沿用 [CONTEXT.md](../../CONTEXT.md) 中的 Workspace、Project、Record、File、File Version、Internal Reference。

实施本需求时，先读[实施 Handover](project-content-tabs-handover.md)，按其中的接收检查、工作包和证据要求推进。

## 1. 需求结论与确认范围

### 1.1 用户已确认

1. 保留现有项目级 Tab，每个外层 Tab 代表一个 Project。
2. 每个 Project 拥有自己的内容 Tab 和布局状态，项目间相互独立。
3. 内容 Tab 支持 File 预览、Record 编辑和会话；它们可以放入任意一栏。
4. 内容区域默认单栏，用户点击分栏后才进入左右双栏，最多同时显示两个内容页面；普通打开内容不自动触发分栏。
5. 双栏时左右各有自己的 Tab 栏、打开列表和选中项，可以独立切换；可以打开的 Tab 总数不限于两个。
6. 分栏交互参考 DSH Desktop 的预览；文件预览复用并适配 DSH Desktop 能力，Record 使用主应用现有编辑器。
7. 纳入 Project 目录管理的 File 必须具有稳定身份，统一管理改名、移动和版本变化；与文件引用一起设计，不能把文件名或路径当成永久身份。
8. 同一 Project 内，每个 File、Record 或会话只能打开一个内容 Tab，包括左右两栏；再次打开时定位并聚焦已有 Tab，不创建副本。文件版本不构成第二个 File Tab 的身份。
9. 2026-10-13 界面优化确认：File 工具栏压成一行，正常阅读不常驻文件位置；提供外部应用打开和小型引用按钮。引用直接新建当前 Project 的会话并插入固定版本草稿，不选择已有会话，也不自动发送。
10. 内容 Tab 参照 Project Tab 的样式，以拖动完成排序和跨栏移动，移除位置小菜单；保留键盘操作，优化大量 Tab 的滚动与边缘提示。
11. Markdown 直接编辑及 `.md` 保存本轮暂停，后续单独设计；当前阅读和源码定位能力继续保留，不新增纯文本阅读切换。
12. 2026-10-15 确认：移除独立的“项目概览”操作行和放大当前栏功能。项目首页显示在左栏内容区；单栏或双栏都只在左栏 Tab 最前面保留一个固定 Home 图标，侧栏项目名称也能打开首页。切换首页保留原有内容 Tab 和另一栏状态。
13. 分栏按钮位于单栏 Tab 栏末端，合并按钮位于双栏右侧 Tab 栏末端，均仅显示图标。顶部选中的 Project 标签主体使用下方内容 Tab 栏的白色底色；两侧弧形保留轮廓，衔接处填色与主体一致，避免浅灰色残角。

### 1.2 建议默认值

以下属于补齐行为所需的建议规则，尚未逐项单独确认；实施排期前可调整，但不得遗漏对应验收。

| 项目 | 建议默认值 |
| --- | --- |
| 新内容打开位置 | 当前聚焦栏；已处于双栏时，从会话点击尚未打开的文件引用优先在另一栏打开；单栏时仍在当前栏打开 |
| 新分栏 | 将当前选中内容 Tab 移至新栏；左栏无剩余 Tab 时显示首页。首页选中时建立空右栏，首页留在左栏 |
| 分栏比例 | 初始 50% / 50%，拖动受各内容最小可用宽度约束 |
| 合并分栏 | 合并两个 Tab 列表，保留对象和状态；显示合并前聚焦栏的选中项 |
| 空栏 | 关闭左栏最后一个内容 Tab 后显示首页并保留双栏；关闭右栏最后一个 Tab 后合并。整个项目无内容 Tab 时显示左栏首页 |
| 不同对象并排 | 不同 File、不同 Record、不同会话可同时显示；同一对象只保留一个 Tab，遵循已确认规则 |
| 窄窗口 | 暂时显示聚焦栏，可切换另一栏；保留双栏成员、选中项和比例，变宽后恢复 |
| 目录排除 | 应用内部数据目录不纳管为业务 File；其他排除规则在实施前列明并在产品中可查看，不以扫描失败充当排除 |
| 跨项目后台执行 | 2026-10-11 实施会话确认：首版支持跨 Project 后台并行；切换项目不停止原任务，各 Project 保留独立运行时与会话绑定，返回后可查看历史并停止目标任务 |

## 2. 目标与非目标

### 2.1 目标

- 在同一 Project 内并排阅读材料、编辑 Record、与助手交互。
- 打开多个内容对象后可以快速切换，恢复各自的阅读或编辑位置。
- File 从目录纳管、预览、版本历史、Record 引用到会话引用使用同一权威身份和版本。
- 关闭、移动、隐藏 Tab 不改变业务对象，不丢失已提交内容，也不隐式停止会话任务。
- 文件能力在没有打开会话、没有配置 AI 模型时仍能使用。

### 2.2 非目标

- 三栏及以上、上下分栏、浮窗、跨窗口拖放、任意布局树编辑。
- 在本包中新建通用插件平台、任意浏览器扩展加载器或第二套业务数据库。
- 重写 Record 编辑器、改变未接受 AI 预览的保存规则。
- 以文件预览代替文件编辑；Office 编辑与原格式回存继续属于 #118 的格式工作包。
- 首版跨 Project 移动 File、跨 Project 引用、跨设备同步布局。
- 保证捕获文件系统发生过的每一次瞬时写入；须可靠保存应用已确认、实际引用的版本，并在打开／读取时核验当前状态。

## 3. 产品结构与职责

```text
Workspace
└─ 项目级 Tab：Project A | Project B
   └─ 当前 Project 的内容区域
      ├─ 左栏：Tab 列表 + 当前内容页
      └─ 右栏：Tab 列表 + 当前内容页（仅双栏）
```

| 所属层 | 责任 |
| --- | --- |
| 主应用项目导航 | Project 选择、目录绑定、内容列表和打开入口 |
| 主应用内容布局 | 两栏、Tab 排序／移动／关闭、聚焦、布局恢复 |
| 主应用 File 服务 | File 身份、实际归属、位置、读取、快照、版本、引用与变化通知 |
| DSH 文件预览适配 | 格式渲染、分页、缩放、行定位和预览控件；通过主应用读取接口获得数据 |
| 主应用 Record 编辑器 | canonical 正文、编辑状态、保存协调、历史与冲突处理 |
| DSH 会话组件 | 明确 Session 绑定的 Chat、Trajectory、输入、流式事件和停止 |
| 主应用运行时与设置 | Project 范围、统一模型、凭据、插件设置和任务生命周期 |

会话中的 Chat / Trajectory 是该会话页面内部的视图切换，不占用第三个项目内容栏。DSH 原预览侧栏的会话归属、开合外壳和全屏规则不作为主应用布局的权威状态。

## 4. 项目内容 Tab 与双栏行为

### T01 项目隔离

- 布局按 Workspace 稳定 ID 和 Project ID 隔离，不以目录字符串或项目名称键控。
- 保存每栏的 Tab 成员及顺序、选中项、聚焦栏、单／双栏模式和比例。
- 切换项目恢复目标项目自己的布局；不将前一项目的 Tab、标题、请求或流式事件送入目标页面。
- 同一 Workspace 下不同 Project 中数值相同的对象 ID，也必须按真实归属解析。
- 没有已保存布局的 Project 默认单栏；只有显式点击分栏控件才建立双栏。恢复该 Project 已保存的双栏布局不属于自动创建新分栏。

### T02 打开、切换与关闭

- 文件列表、记录列表、会话列表、搜索结果、最近访问和内部引用统一调用内容打开入口。
- 默认打开到聚焦栏；已处于双栏时，“在另一栏打开”可以指定目标栏。单栏时普通打开、引用跳转和深链接都不自动建立双栏。
- 唯一性按 Workspace、Project、对象类型和稳定对象 ID 判断，覆盖该 Project 的全部栏；文件查看版本、标题、路径和打开入口不参与 Tab 唯一性判定。
- 对象已经打开时，定位到其所在栏并聚焦已有 Tab，更新本次明确请求的内容定位，不创建第二个 Tab，也不因目标栏不同而复制或自动移动它。
- 普通重复打开只定位已有 Tab，保留其当前查看版本和视图状态；明确打开历史引用或用户切换版本时，在同一个 File Tab 内切换到请求版本及定位，标题明确标示历史版本。最新版和历史版本不得分别打开成两个 Tab。
- Tab 标题显示文件名、Record 标题或会话标题；业务标题变化更新展示，Tab ID 保持稳定。
- 关闭 Tab 仅关闭展示。删除 Record、删除 File、移除会话属于独立操作，不复用关闭按钮。
- 关闭失败时保留 Tab 并显示原因；保存失败不能先关闭再丢弃内容。

### T03 分栏、移动与合并

- 分栏控件可发现；Tab 用拖动排序和跨栏移动，不提供位置小菜单。支持键盘替代路径与插入位置提示，拖至溢出边缘可继续滚动。
- 支持栏内 Tab 排序和左右跨栏移动；第三栏始终不可创建。
- 移动改变 Tab 所在栏，不改变业务身份、查看版本或会话绑定。
- 左右栏共享项目级对象唯一性；移动只能转移已有 Tab，不能保留原栏副本。点击引用不会替代用户显式移动操作。
- 分隔条可拖动，调整期间页面按容器尺寸重新布局。
- 合并不删除 Tab；空栏规则依 1.2 执行。拖动或合并不能丢失草稿、撤销栈、选择和阅读状态。
- 不提供放大当前栏；窄窗口仍临时显示聚焦栏，并在当前栏 Tab 栏中提供切换另一栏的图标。
- 首页为左栏固定页面，使用同一内容网格，不覆盖整个双栏。Home 不进入可关闭内容 Tab 列表；切回普通内容时保留唯一首页实例及其编辑状态。
- Tab 使用 Project Tab 的颜色、圆角和关闭行为，按 File / Record / Session 显示类型；运行标记来自该 Session 的真实状态。横向滚动条保持轻量，仅在实际有隐藏内容的方向显示连续边缘遮罩。

### T04 焦点与键盘

- 两个选中页面都属于“可见”，只有当前操作栏属于“聚焦”；禁止用一个全局 active 标志同时表达这两个概念。
- 点击页面、Tab 或通过键盘切换后更新聚焦栏；保存、关闭 Tab、Tab 切换等命令作用于正确页面。
- 当前焦点在弹窗或编辑菜单中时，先处理该层，不关闭后方 Tab 或应用窗口。
- 明确页面快捷键和操作系统原生关窗快捷键的分工，避免误关窗口。
- 新内容可以按打开意图获取焦点；后台数据到达、自动刷新、另一栏流式输出不抢夺编辑器焦点。

### T05 恢复与失效

- 应用重新打开后恢复布局描述，并按需加载可见内容；不为恢复布局自动启动所有后台会话。
- 已不存在、无权访问或已被移除的对象显示可关闭的失效页；不按旧路径寻找别的对象替代。
- 损坏的布局只清理相应 Project 的布局数据，保留业务内容及其他项目布局。
- 历史版本不存在时明确显示不可用，不能替换成最新版本。
- 窄窗口保留另一栏的完整状态；自动适配不能成为不可逆的布局合并。

## 5. File 身份、目录纳管与版本

### F01 统一身份

- 复用现有 File 身份；实现字段可沿用 `documents.id` / `documentId`，对外领域名称为 File / `fileId`。
- 不为目录文件、已导入文件、助手产出分别建立互不关联的身份仓库。
- 身份解析以 Workspace 和真实 Project 归属为边界。名称、当前相对路径、绝对路径、内容哈希、系统文件标识均不是业务 ID。
- 同一 Project 内已纳管 File 改名或移动时保持 ID；两个内容相同的独立文件保留独立 ID。
- 同一物理目标通过不同路径入口访问时需要识别已登记归属，不能无意重复纳管。symlink、越界和多项目目录重叠的处理须在目录接入边界验证；首版不自动合并跨 Project 的身份。

### F02 纳管范围与登记

- 用户纳入 Project 目录管理的普通业务文件都进入统一目录，不因无法预览而拒绝登记。
- 首次纳管建立稳定身份、当前位置、内容状态和可引用的初始版本；读取失败或无法建立快照时显示待登记／不可用，不能假称已形成版本。
- 保留文件在真实项目目录，历史快照由现有 File Version 存储管理；目录纳管不得擅自搬走用户文件或修改业务内容。
- 现有已导入 File 和目录文件入口通过权威位置与归属映射统一识别，不能仅凭 basename 或 hash 合并。
- 扫描展示进度和失败；取消后已成功登记的条目可复用，重复扫描不重复创建 File 或版本。
- 自动监听和人工刷新共用同一登记／核对行为；应用重新打开时核对离线期间的变化。

### F03 改名、移动与缺失

| 变化 | 要求 |
| --- | --- |
| 应用内改名、同项目移动 | File ID 不变，位置及展示名更新；已打开 Tab 和引用继续解析同一 File |
| 外部改名、移动 | 依据平台事件和已有登记证据恢复映射；无法确定时显示待确认，不按猜测重绑引用 |
| 编辑器原子替换同一路径文件 | 识别为当前 File 的内容变化时登记新版本；不能仅因 inode 改变就创建新 File |
| 旧文件删除后路径被新文件占用 | 不因路径相同继承旧 ID；无法区分的情况进入明确核对流程 |
| 文件暂时缺失或不可读 | 保留 ID、版本和引用，标记状态，不清空布局或引用边 |
| 用户确认重定位 | 核验选定内容与目标身份；内容不同不能以“修复路径”悄悄替换已登记版本 |
| 复制文件 | 新的独立 File；内容哈希可以相同，但引用身份不合并 |

文件系统事件用于提示变化，不作为文件身份和版本提交的唯一依据。对无法证明的外部变化必须暴露歧义；初版不承诺所有平台都能无提示识别所有外部改名组合。

### F04 File Version

- 同一 File 的内容变化形成新的不可变 File Version；单纯改名不形成内容版本。
- 复用现有版本编号、内容哈希、快照、版本 CAS、提交回执和恢复机制。
- 登记时核验实际读取的字节；文件读取中变化时不能混合内容，也不能把旧版本标签贴到新内容上。
- 未登记的外部字节不能显示为旧版本已确认内容。刷新或引用前应先形成一致的已登记版本，失败时显式阻止该次版本引用。
- 恢复历史内容创建新版本，保留原版本及来源；不倒改历史版本。
- 存储中的历史版本具有可找回的内容快照。仅保存 hash 或曾经的路径不构成历史内容可恢复。
- 第一版不在本包新增自动清理策略；现有保留政策若允许清理被引用的版本，必须与引用保护协调后才启用，不静默丢失引用目标。

### F05 外部写入与助手写入

- 外部写入后核对内容并登记已确认版本，刷新相应 File Tab 和当前版本元数据。
- 助手在实际项目目录生成的新文件进入同一纳管流程，续改已纳管 File 保持身份。
- DSH 工具原始路径结果必须经主应用归属解析和版本登记后，才成为权威 File 成果链接或固定版本引用。
- 应用内已有的文件写入、版本服务和并发核验继续复用；Tab 层不直接覆盖文件以绕开原生提交服务。
- 通知是刷新提示；接收方按 File ID 和版本重新读取权威结果，并拒绝过期 Project 或 Workspace 代次的返回。

## 6. 统一文件引用

### R01 两种引用语义

| 类型 | 用途 | 解析规则 |
| --- | --- | --- |
| 当前文件导航 | 文件列表、最近访问、普通“打开文件” | 稳定 File ID，打开时解析当前已登记版本 |
| 内容依据引用 | Record 中引用材料、会话实际读取的文件／片段、成果依据 | 稳定 File ID + 固定 File Version + revision/hash + 可选定位与摘录 |

引用复用现有 `ObjectRef` / `SourceRef` 和 Internal Reference 关系，不建立 DSH 专属引用数据库。已有字段不足时只补真实使用的定位类型。Project 内容仅引用本 Project 内的对象；Workspace 范围引用仍遵循既有领域规则。

### R02 创建和发送

- 选择文件后草稿持有稳定 File 身份及显示信息，不只插入一个路径字符串。
- 创建正式内容引用时解析实际读取的版本；会话发送成功后持久化该版本依据，之后不随当前版本漂移。
- 选择到提交期间文件变化时，必须明确采用最终实际读取的版本，或提示重新确认；不能显示一个版本却向模型发送另一个版本。
- 若模型执行过程中读取了后续版本，该次实际读取的依据单独记录，不能回写之前已固定的消息引用。
- 无法读取、版本未登记、归属不符或对象失效时显示真实原因，不声称已向模型提供内容。
- 预览行为本身不会自动把内容加入模型请求。路径型外部链接仍可作为普通链接显示，不伪造为已登记引用。

### R03 展示和跳转

- 改名或移动后仍按身份解析；固定引用保留当时的版本、摘录和定位信息。
- 页面可展示当前名称，并在引用详情显示引用时名称／位置与固定版本，避免混淆。
- 点击内容依据在该 File 唯一的 Tab 中打开对应历史版本；已打开则定位已有 Tab 并切换到引用指定版本及位置。提供显式“查看最新版”，也在同一 Tab 内切换，不隐式升级引用或另开版本 Tab。
- 行范围、PDF 页码或其他定位必须解释为被引用版本内的位置；该渲染器无法定位时说明原因并提供适用查看器。
- 缺失、删除、版本不可用或权限变化时保留引用本身，显示相应状态，不按相同文件名寻找替代目标。
- 关闭内容 Tab、移除会话不能级联删除 File、Record 或业务引用与提交回执。

## 7. DSH 文件预览适配

### P01 数据与宿主脱离

- 复用固定来源的 DSH 预览源码，保留许可、依赖与本地修改记录。
- 输入改为主应用 File / File Version 描述及 Tab 生命周期；读取、元数据、变化通知、关联资源解析由主应用提供。
- 预览不要求先选择 Session，不自动创建辅助会话，不依赖模型配置、登录或会话仍存在。
- DSH 原 Session 文件地址仅作旧入口转换；成功解析后使用统一 File 身份，不以当前 Session 临时补全另一文件的归属。
- 原 `useTabInfo`、资源 pin、store 和取消机制可以适配，但不能让原会话侧栏成为项目布局或业务内容的第二份权威状态。

### P02 格式与能力边界

| 首版范围 | 验收要求 |
| --- | --- |
| 纯文本、代码 | 分页、完整性状态、换行、复制、固定版本行定位 |
| Markdown | 渲染已支持语法、项目内图片／资源；提供源码查看与行定位入口 |
| 常见图片 | 显示、缩放、尺寸变化适配；正确释放临时资源 |
| PDF | 实际页面、分页／滚动、缩放及页定位；Worker 和字节生命周期正确 |
| HTML | 沿用 #115 隔离要求；静态或交互模式明确，资源与脚本错误如实展示 |
| 不支持或超限格式 | 身份和版本仍可管理，显示限制及本地打开入口 |

Excel、Word、PPT 的 DSH 预览与转换可分包接入，仍需真实样例、原生资源和平台验收；不以转换为 PDF 宣称已提供 Office 编辑。#118 中的编辑与回存目标继续保留。

### P03 内容和资源一致性

- 分页来自同一版本；固定历史版本不被自动刷新替换。
- 预览关联图片、CSS 等依赖通过明确的项目归属和读取边界解析，不授予 iframe 任意文件读取或 Tauri IPC。
- 历史 HTML / Markdown 依赖未保留快照时，说明依赖不可用或版本不一致；不能加载当前依赖却宣称整个历史页面完全一致。
- 预览不修改原文件。切版本、重新载入和关闭时取消旧读取，并释放 Blob URL、Worker、转换任务和资源订阅。

### P04 紧凑文件工具栏

- 文件名、查看版本、源码切换、刷新、外部打开和引用组织为单行；长标题可截断，版本语义和历史提示仍可识别。正常阅读不常驻位置操作，缺失或身份异常时保留核对与恢复入口。
- 外部应用打开当前真实原件，历史视图明确说明外部打开不会切换为历史快照；不支持或超限预览的文件同样能使用该入口。失败显示原因。
- 文件侧栏、项目目录与 File Tab 的文件类型图标优先复用 DSH 内置映射；没有映射的类型向主机读取系统文件类型图标，按类型复用查询，不依赖当前原件或历史快照存在。图标加载失败须可发现，不影响文件身份、版本或打开操作。
- “其他应用打开”列出当前文件的系统注册处理应用，所有应用图标均从系统读取，不使用文件类型图标代替。选择应用前再次核验当前 Workspace、File 归属和原件身份；应用关联变化或打开失败显示原因。默认应用打开入口保留，历史视图下两种入口都打开当前原件。
- Markdown 继续使用已有阅读渲染与源码定位。本轮不新增直接编辑或原格式保存链路；编辑、从历史版本继续修改、资源回存及保存冲突在后续工作包共同设计。

## 8. Record 编辑页面

### E01 两条不同 Record 同时编辑

- 每个 Record Tab 通过明确的 Project 和 Record ID 加载，不依赖唯一的全局路由作为编辑目标。
- 两个可见编辑器独立保存、选择、光标、撤销栈、历史和冲突状态。
- 共享现有保存协调与 canonical 正文服务，保持按 Record 身份隔离，不建立 Tab 专属正文副本。
- 当前全局最多缓存两条 Record 的逻辑不能直接当作已支持双栏；需适配双可见页和后台 Tab 的草稿生命周期。

### E02 保存、移动和关闭

- 栏内切换、跨栏移动、项目切换不丢失普通编辑；隐藏页不抢焦点、不持续执行仅属于可见页的 UI 任务。
- 关闭执行对应 Record 的保存／离开协调。保存失败、冲突、忙碌或未完成操作时保留页面并说明处理入口。
- 未接受 AI Modification / AI Answer 不因关闭、卸载或自动保存成为 Committed Content，遵循 ADR-0003。
- 现有合法 Agent Record 提交仍按 ADR-0009 / ADR-0010 协调目标编辑器；双栏不放宽归属、版本 CAS 或提交锁。
- 不把关闭编辑 Tab 等同于接受、放弃或删除待审阅 AI 修改。

## 9. 会话页面

### C01 明确绑定和共享运行时

- 每个会话 Tab 绑定其真实 Project 与 Session ID；两个不同会话可同时显示，不能共用一个全局“当前 Session”覆盖彼此。
- 同 Project 的页面共享适用运行时、模型和插件配置，Session 引用、输入、历史和事件按会话隔离。
- 会话内提供统一模型设置入口；运行时显示该 Session 实际使用的模型，空闲时显示下一次选择或最近记录。尚无实际模型记录时不拿共享默认配置冒充当前运行模型。
- 两栏会话均提供真实 Chat / Trajectory、发送、流式、停止、工具结果与失败恢复；不因另一栏获取焦点而重置状态。
- 若运行时限制并发执行，第二个发送应给出明确限制且保留草稿，不静默取消第一个任务或误路由消息。

### C02 隐藏、关闭和项目切换

- Tab 切换、移动和关闭视图不自动停止已提交任务。运行状态在项目会话列表及适用 Tab 中可发现。
- 关闭正在运行的会话页后，用户仍能从项目会话入口找到运行中任务并打开、停止。
- 隐藏页可按需卸载展示，但执行和持久历史由运行时管理；不能依靠 React 页面保活保证任务存续。
- 首版支持跨 Project 后台并行。切换项目不停止原任务，各 Project 的运行时、输入、输出和停止目标独立；仅有 File / Record 内容的项目无需启动运行时。
- 打开仅有 File / Record 的项目内容时，不为布局恢复启动 AI runtime。

### C03 文件入口

- 文件卡片、工具产出和轨迹文件链接统一交给主应用 File 解析与内容打开入口。
- 有版本依据的链接打开固定版本；只有路径的链接先解析和纳管，不能虚构历史版本。
- File Tab 小型引用按钮先核验正在查看的固定版本、归属和工作区代次，再新建当前 Project 的会话；仅插入该版本引用草稿，不自动发送。忙碌时防重复触发；取消后不继续投递，失败可显式重试，不串入另一栏已有会话。

## 10. 状态与接口约束

以下是逻辑模型，不要求新建同名数据库表或重写已有 DTO。

| 状态 | 最小内容 | 持久化边界 |
| --- | --- | --- |
| Project 布局 | Workspace ID、Project ID、栏成员、选中项、聚焦栏、比例 | 保存布局描述，不保存业务正文 |
| Tab | 稳定 Tab ID、类型、对象身份、当前 latest／固定版本查看目标 | 项目内按对象唯一；版本仅为查看状态，与对象生命周期分离 |
| File | 稳定 ID、归属、当前位置、当前版本、健康状态 | 现有 File 服务扩展 |
| File Version | File ID、版本编号、hash、不可变快照定位 | 现有 File Version 权威存储 |
| 内容引用 | ObjectRef、固定版本／revision、定位、标题和摘录 | 现有引用关系与来源描述 |
| 页面视图 | 光标、滚动、缩放、查看器、输入草稿 | 按对象／Tab 明确管理；不得混入历史文件内容 |

- 路由用于导航和恢复当前目标，不能是两个页面唯一共享的编辑上下文。深链接应落到正确 Project、对象和版本，随后与布局协调。
- 读取、写入、请求取消和事件投递明确携带对象及作用域；跨异步后核对 Workspace 代次与目标仍有效。
- 输入边界验证权威归属，主应用通过 File ID 解析路径；不能因前端提供 File ID 就跳过实际权限检查。
- 布局持久化不保存密钥、正文、二进制字节或活动连接；恢复权限不从 localStorage 推导。
- Project 目录重新绑定需验证文件位置映射，不能清空所有 File ID 或静默把旧引用指向新目录的同名文件。

## 11. 视觉、性能与资源生命周期

- 主应用设计系统负责 Tab、分栏 chrome、菜单、焦点及主题；DSH 预览和会话组件继承容器主题与尺寸。
- Tab 栏可横向滚动，左右各自处理溢出；内容列表遵循[设计系统](../design-system.md)中的“滚动区域与边缘遮罩”规范。无溢出无渐变，有溢出按实际距离连续消失，内容／尺寸变化后更新。
- 分栏、合并和窄屏变化采用连续过渡，尊重 reduced-motion；拖动宽度跟随指针。
- 两个可见页各自滚动，滚动一个页不带动另一个页；窗口级菜单定位不把两栏编辑器选区混在一起。
- 后台 Tab 的元数据和视图状态可保留，但不永久挂载所有重型编辑器、PDF Worker 或 HTML 执行环境。
- 卸载重型页面前可靠保留必要草稿和阅读状态；跨栏移动后不能重置 Record 撤销栈。具体保活方式由实现验证后决定。
- 原生读取上限、分页和资源预算沿用已有边界。超限给出解释，不静默截断为“完整预览”。

## 12. 迁移与兼容

1. 保留已存在的 File ID、File Version、Record ID、会话历史和引用；目录登记不得重编号现有对象。
2. 现有单文件预览和路径型目录入口迁入统一内容打开入口，不长期维护彼此独立的 Tab 状态。
3. 旧路径链接可以尝试按当前项目登记目录转换；映射不明确时保留普通路径链接或显示待定位，不能伪造稳定引用。
4. 没有历史版本信息的旧会话路径，不能追溯认定为某个当时版本；首次解析只能说明当前登记结果。
5. 现有固定版本引用继续固定，不因为新 UI 自动升级为 latest。
6. 旧布局可转换为单栏；业务数据库迁移遵循已有备份和事务机制，不为纯布局改动重建业务数据。
7. 与 #118 的格式编辑、HTML 隔离目标协作，不以本包只读预览完成关闭格式编辑 Issue。
8. 本文不改变 ADR-0003、ADR-0009 或 ADR-0010；如实现提出冲突方案，需明确列出并单独决策。
