# 项目内容 Tab 与统一文件管理：实施 Handover

更新：2026-10-13。接收对象：负责本功能的实施 agent。状态：集成实现与本轮 macOS 复验已记录，Windows 及扩展产品验收保留待办，见[执行记录](project-content-tabs-execution.md)。

## 1. 接收任务与权威规格

在主应用现有项目级 Tab 下实现项目独立的内容 Tab，接入 File 预览、Record 编辑和 DSH 会话，支持默认单栏及用户主动建立的左右双栏，同时统一项目文件身份、版本与引用。

先读[完整需求](project-content-tabs.md)。本文负责执行顺序和交接，产品规则与 A01–A32 验收以完整需求为准；用户在实施会话中的新指令优先，并同步更新规格。本文不表示已有实现通过验收，也不授权重做其他正在进行的工作。

### 已确认、直接实施的规则

- 保留外层项目 Tab；内层布局属于 Project，包含各栏自己的 Tab 列表、选中项和聚焦栏。
- 新项目内容布局默认单栏。用户点击分栏才建立双栏；普通打开、引用和深链接不自动分栏。可以恢复用户此前保存的双栏布局。
- 最多显示两页，可以打开多个 Tab；左右各自切换、滚动与操作。
- 同一项目内，一个 File、Record 或会话只对应一个 Tab。唯一性覆盖左右两栏；再次打开定位并聚焦其已有 Tab，不复制、不自动移栏。
- File 按稳定 ID 去重，版本属于查看状态。历史引用在同一 File Tab 内切换到指定版本；普通重复打开保留当前查看版本。
- File 预览使用适配后的 DSH 能力，Record 使用现有编辑器；文件浏览属于主应用，文件预览无需 Session 或 AI 模型。
- 项目文件改名、同项目移动保持身份；确认的内容更新形成不可变版本。文件引用沿用主应用身份、归属和来源体系。

完整需求 §1.2 为建议默认值，§15 为待决策边界。常规交互可以按建议先做可评审实现，记录采用的值；涉及历史清理、存储预算、外部文件身份歧义和跨项目运行能力时，在相关工作包中形成明确决策。用户已确认首版需要跨项目后台并行；按完整需求 A27 实施 Project 独立运行时，运行中切换 Project 不停止原任务。

## 2. 开始执行

按以下顺序完成接收检查，再修改源码。

1. 阅读仓库 [AGENTS.md](../../AGENTS.md)、[领域上下文](../../CONTEXT.md)及相关 ADR；涉及 Record 保存与 Agent 写入时，必读 [ADR-0003](../adr/0003-persist-only-committed-editor-content.md)、[ADR-0009](../adr/0009-bind-agent-operations-to-workspace-and-atomic-receipts.md)、[ADR-0010](../adr/0010-separate-agent-record-commits-from-editor-skill-previews.md)。
2. 读取当前分支、工作树变更和现有实现。确认本任务与正在进行的 DSH 接入、文件能力工作是否共享文件；保护现有未提交改动，复用适用 checkout，必要时按接收会话授权协调隔离。
3. 修改源码前检查 `tauri dev` 自动重启进程。若存在监听，先协调监听与编辑安排，避免源码变更反复启动窗口；终止用户进程必须有适用授权。
4. 按[议题跟踪规则](../agents/issue-tracker.md)读取相关 Issue。既有 #118 覆盖文件格式能力，不自动等同本功能父 Issue；在有相应授权的实施会话中关联或建立真实工单，不编造编号。
5. 写出当前工作包的 Issue、依赖、修改范围、交付行为、非目标、验收编号及验证命令。先核实当前脚本和测试入口，再执行，避免复制过期命令。

**完成条件：** 接收记录中有当前代码基线、已存在能力、缺口、工作包范围和测试范围；必要决策有采用值或具体待解锁条件。源码变更不会覆盖其他工作的成果或反复拉起窗口。

## 3. 先确定状态与打开入口

在真实页面接入前确定最小布局模型和统一打开协议。复用主应用状态体系，不以 DSH 的 Session 侧栏状态作为项目布局权威。

### 必须保持的不变量

| 概念 | 规则 |
| --- | --- |
| 布局键 | Workspace 稳定 ID + Project ID |
| 对象键 | 布局作用域 + 对象类型 + 稳定对象 ID；File Version、名称和路径不参与去重 |
| 栏 | 一个或两个；每栏有 Tab 顺序和选中项，整个布局有一个聚焦栏 |
| Tab | 在该项目布局中只有一份，归属一个栏；移动保持 Tab 身份 |
| 页面状态 | 可见与聚焦分别表达；两个选中页同时可见，只有操作目标聚焦 |
| File 查看 | latest 或固定版本、定位、缩放与滚动属于同一 File Tab 的查看状态 |
| 业务内容 | File、Record、会话历史由已有业务服务管理；布局保存不复制正文或字节 |

统一打开入口应接收对象身份、可选版本／定位和打开意图。处理顺序：

1. 在权威边界核验 Workspace、Project 与对象真实归属。
2. 在整个 Project 布局查找已有对象 Tab。
3. 已存在则激活其所在栏和 Tab；普通打开保留视图，明确的版本／定位请求更新该 Tab 的查看目标。
4. 不存在则在合法目标栏创建；单栏的普通打开只使用现有栏。
5. 分栏、移栏、合并使用明确布局操作；只有分栏控件建立第二栏。

去重必须在状态变更时成立，包括两个入口同时请求打开同一对象的情况；异步加载完成顺序不得产生重复 Tab。具体同步机制使用现有状态约定，不新增通用事务框架。

**完成条件：** 新项目默认单栏；多入口重复打开与跨栏重复打开均只有一个对象 Tab；普通打开不分栏；历史与最新版本共用 Tab；分栏、移动、合并、恢复满足 A01–A09 的布局部分。至少接入一个真实业务页面验证，演示占位页不算交付。

## 4. 按工作包交付

编号沿用完整需求 §14，不用新的编号替换验收追踪。WP1 与 WP2 的独立部分可先推进；其余按真实依赖接入。

### WP1：统一 File、版本与引用

- 复用现有 File / File Version 身份、快照、CAS、提交回执与来源登记；将项目目录入口纳入同一服务。
- 保留用户文件的实际目录位置；纳管涵盖不能预览的业务文件，失败和排除可见。
- 验证应用内改名／移动、外部变更、原子保存、旧路径被新文件占用、相同内容的不同文件和离线变化。证据不足时暴露歧义，不能按路径或 hash 猜测身份。
- 区分当前文件导航和固定内容依据，Record 与会话复用 ObjectRef / SourceRef。确认版本与实际读取字节一致，再形成正式引用。
- 既有已登记版本保持不可变；历史恢复形成新版本；已引用历史的保留政策明确后再实施清理行为。

**完成条件：** A10–A20、A29–A30 的文件与引用范围有真实数据和测试证据；路径型入口通过权威解析接入；保留既有 ID，未知历史不伪造。模型实际读取依据还依赖 WP5 时明确标为待集成，不能提前宣称 A19 完成。

### WP2：项目独立内容布局

- 实施第 3 节模型，接入项目切换、独立 Tab 栏、显式分栏、排序／移动／合并、焦点、关闭协调和布局恢复。
- 默认值按完整需求 §1.2；新分栏空态与最后 Tab 关闭行为分别处理。
- 先接入真实 Record 入口建立可用纵向链路；File 和会话后续共用相同打开入口。
- 无效对象保留可关闭状态页，损坏布局局部恢复；窄窗口保留原双栏描述。
- 关闭协调等页面行为依赖页面接入，不能只凭布局 reducer 用例认定整体完成。

**完成条件：** A01–A09、A31–A32 中适用范围通过，所有打开入口逐项列明接入／待接入状态；仍待 WP3–WP5 的行为保持开放。

### WP3：Record 编辑器

- 明确传入 Project / Record 身份，适配现有居民页缓存与路由，支持两个不同 Record 同时可见。
- 复用 canonical 编辑器和保存协调；检查全局快捷键、选区、菜单、自动聚焦及编辑器注册是否命中正确页。
- 移动、隐藏、合并前后保留草稿、光标和撤销栈；关闭时处理保存失败、版本冲突及待审阅 AI 修改。
- 未接受 AI 预览不因自动保存或卸载成为 Committed Content；合法 Agent 写入继续遵循现有锁与 CAS。

**完成条件：** 用两个真实 Record 验证 A04–A05、A08、A24、A28；重复打开同一 Record 只有一个编辑实例；保存失败时 Tab 与内容仍可恢复。

### WP4：DSH File 预览

- 从固定来源核验并适配所需 DSH 预览源码及依赖，维持许可、资源和修改来源记录。
- 将 Session + path 读取改为主应用 File / File Version 读取；关联资源按项目归属解析。
- 绑定主应用 Tab 生命周期，处理版本切换、分页一致性、定位、重载与取消、Blob URL／Worker／订阅释放。
- 验证文本、代码、Markdown、图片、PDF、HTML 的真实样例；HTML 隔离沿用 #115 要求。
- 历史资源未保存时显示实际限制。Office 预览是否纳入按规格 §15 决策，Office 编辑继续归 #118。

**完成条件：** A17–A23、A28 的预览范围通过；模型未配置且没有 Session 时可预览；切换历史版本仍只有一个 File Tab；安装／发布包包含必需资源，而非依赖临时下载目录。

### WP5：DSH 会话

- 核验当前 DSH 接入的实际进度，复用真实 Chat / Trajectory 链路；每个页面绑定独立 Session，不共用单一可变当前会话引用。
- 两个不同会话可以显示与操作，输入、历史、流式、停止及错误归属正确；运行时若限制并发，应显式反馈并保留草稿。
- 隐藏或关闭页面不隐式停止执行；项目会话入口继续能发现、重新打开和停止任务。
- 适配文件卡片、工具产出、轨迹与草稿引用到主应用 File 服务，补齐 WP1 留下的实际模型读取依据。
- 首版提供跨 Project 后台并行；按 Project 绑定运行时与停止目标，切换后保留任务、草稿和历史。

**完成条件：** A18–A20、A25–A28 的会话范围通过；同一会话只有一个 Tab；两会话操作不串流、不互相误停止；原始路径不伪装成固定历史引用。

### WP6：迁移与产品收口

- 清点文件列表、Record 列表、会话列表、搜索、最近访问、内部引用与旧预览入口，统一迁入内容打开入口。
- 验证旧身份、已固定引用、旧路径链接、布局迁移以及跨端 DTO／事件；保留其他工作包的目标和数据。
- 检查主题、窄窗、键盘、连续过渡、实际溢出遮罩和重型资源释放。
- 对完整需求 A01–A32 逐项记录通过、未通过、待平台验收或经决策调整后的范围；任何未交付的确认需求必须保留明确状态。

**完成条件：** 实际交付范围有完整证据、主应用入口真实可用、Standards / Spec 检查完成且发现已处理。发布按接收会话授权及[仓库发布流程](../agents/publish-flow.md)执行；只读预览完成不能关闭尚包含格式编辑的 #118。

## 6. 验证与交接记录

按工作包记录证据，不用全量测试替代失败诊断。复用未受新修改影响的通过结果，记录覆盖的提交或改动范围。编译和单元测试静默；真实 GUI 验收集中执行，提前告知用户。macOS 与 Windows 验收分别标记，未提供的平台不能写为通过。

关键测试应覆盖可观察结果：项目隔离、全项目去重、显式分栏、并发打开、移栏状态保留、双编辑器保存隔离、会话绑定、真实版本引用、外部文件身份歧义及延迟返回。格式样例和原生边界分别测试，测试替身不代替真实业务接入。

实现 agent 的安排以接收会话权限为准；本 handover 不覆盖禁止子 agent 的会话限制。Review 子 agent 必须先取得适用的用户明确同意；没有同意时由负责 agent 自行完成两个 review 轴。

每包结束交付：

```text
工作包 / Issue：
代码基线与本次改动范围：
交付行为与接入入口：
采纳默认值 / 新决策：
验收编号：逐项结果及证据
验证：命令、结果、覆盖范围、复用依据
Review：Standards / Spec 结果与发现处理
剩余问题：影响、具体解锁条件、对应工作包
下一步：可直接开始的工作及依赖
```

真实业务接缝或目标平台缺失时，交接写明缺少哪项能力、需要谁提供什么，以及仍可独立执行的工作。所有确认需求完成后再报告整项交付；阶段提交、底层服务通过或 UI 占位均只计入对应阶段。
