# AI 调用的系统代理与自定义代理

更新：2026-10-10。关联 [#119](https://github.com/xuchen-cloud/project_mind/issues/119)，属于 AI 增强 #97。

用户需要在产品内选择 AI 调用如何联网。在“设置 → AI 模型 → AI 连接”中提供三种方式：

| 方式 | 实际行为 |
| --- | --- |
| 系统代理（默认） | 优先使用应用启动环境中相应的 HTTP_PROXY / HTTPS_PROXY；未指定时，读取 macOS 的静态 HTTP/HTTPS 代理或 Windows 当前用户的统一静态代理。ALL_PROXY 与 NO_PROXY 按上游规则处理。没有代理时直连。 |
| 自定义代理 | 填写一个 HTTP 或 HTTPS 代理地址，例如 `http://127.0.0.1:7890`。HTTP 和 HTTPS 模型请求都使用它，覆盖环境及系统代理。 |
| 直连 | 忽略环境和系统代理，直接连接服务商。 |

配置随当前 Workspace 的 AI 设置保存，同一 Workspace 的所有模型接入共用。保存后新发起的请求使用新配置，已经开始的请求继续原来的连接；切换 Workspace 时使用该 Workspace 的配置。无需分别设置每个模型的代理。保存失败时保留未保存的输入，不能显示保存成功。

自定义代理支持 HTTP Basic 账号密码认证：可以单独填写用户名、密码，也可以输入 `http://user:password@host:port`。URL 内的特殊字符需按 URL 规则转义；单独输入字段由应用完成转义。URL 内的账号密码优先于单独字段，保存后地址与用户名分开显示。地址仍只允许协议、主机和端口，不接受路径或查询参数；SOCKS 不在本包。

按用户明确要求，账号密码保存为普通本地配置，不加密。设置读取只返回用户名和“密码已保存”状态，不回显密码。留空表示在同一代理地址、同一用户名下保持已保存密码；“清除密码”明确删除密码。改变地址或用户名且没有提供新密码时清除旧密码；切到系统代理或直连时清除自定义凭据。密码不进入模型上下文、会话内容或运行日志；内部连接参数的 Debug 输出也隐去地址及凭据。非法配置不能覆盖原值；设置保存不代表网络可达，用户可使用已有模型配置“测试”按钮检查实际连接。

会话、模型连接测试、后台 Overview/知识/长期记忆整理，以及原生 AI 文本、图片和会议纪要请求统一使用所选方式。代理连接失败按原有请求错误流程报告，不自动换成直连；不新增网络重试或另一套请求框架。

实现复用 `reqwest` / `hyper-util` 的系统代理支持。原生请求依据配置创建 HTTP client，认证随代理连接发送；Rust Host 在每次启动模型会话或连接探测的 Node 子进程时，根据服务商地址解析代理决定，并设置子进程代理变量。Node 继续使用已有 `--use-env-proxy`，不修改系统代理、应用全局环境或 Pi 源码。纯本地会话历史读取不需要服务商代理。模型输入、会话记录和日志不保存代理地址或凭据。

系统代理有明确边界：本包不解析 PAC/WPAD；当前上游 macOS 读取器不读取系统代理例外列表，Windows 支持统一代理地址，按协议分别填写的 `http=…;https=…` 配置尚未覆盖。环境 NO_PROXY 仍按上游规则执行。界面说明静态代理范围，目标平台真实验证另行记录，不能把 Linux 上的模拟规则测试当作 Windows/macOS 已验收。

## 工作包 NP1

依赖：现有 AI 设置、原生 Provider 与打包 Node 运行时。交付：保存配置、设置入口、两条调用链统一接线。非目标：PAC、SOCKS、逐模型代理、全应用网络设置和旧 AI 数据迁入。

验收与验证：

- 新 Workspace 默认系统代理；自定义设置保存并重开后恢复，非法设置不覆盖原值；解析模型配置时带上当前网络设置。单独字段与 URL 认证两种写法均可用，读取不回显密码，保持/清除及身份变化规则正确。
- 界面可选择三种方式，仅自定义显示地址；保存错误保留草稿，成功更新实际设置。
- 本地真实 HTTP 代理收到原生请求和打包 Node 请求，含认证时收到正确的 Proxy-Authorization；HTTPS 请求向代理发起 CONNECT。Node 的 HTTP 请求也可能采用 CONNECT 隧道，不能用是否出现绝对 URL 的 GET 判断是否走代理。
- 直连绕过环境代理；不可用自定义代理报错，目标地址可用时也不自动直连。
- 系统匹配按实际服务商地址和协议执行；环境凭据转发不因 URI 解析丢失。
- 运行受影响 Rust、前端和打包 Node 测试、生产构建及主 agent Standards/Spec 自查。Windows/macOS 真实静态系统设置验证单列缺口。

本包状态以交付计划与 #119 的证据为准，不因需求文档完成而认定产品通过验收。
