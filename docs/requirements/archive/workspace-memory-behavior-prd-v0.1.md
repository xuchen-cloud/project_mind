# Workspace 记忆行为与记忆组件 PRD（草案 v0.1）

Project Mind · 2026-10-10 · 状态：待评审 · 依据：项目现状说明、内部讨论与公开资料调研。文中 \[I1\]、\[E3\] 等为来源编号（见第 13 节）；\[A\] 表示本文的判断或建议，不是来源中的事实。

## 1. 背景与问题

当前 AI 系统已有较完整的持久化、授权、版本与恢复基础 \[I1\]，但记忆部分有四个问题：

1. 记忆只在 Overview 增量整理时产出（按配置 24 或 48 小时一次）。对话里没有即时新增、替换、移除记忆的入口，GUI 之外也无法管理 \[I1\]。
2. 「什么值得记」写死在固定生成 Prompt 和程序里，用户和 Agent 都不能调整 \[I1\]\[I2\]。
3. 每轮只注入约 1500 字符的导航卡片，正文靠按需搜索，而知识搜索只索引标题、别名、关键词和一句话描述，偏好、方法类记忆不保证到场 \[I1\]\[A\]。
4. 记忆归属仍有 Project 和 Workspace 两种，Project 会话不会自动获得 Workspace 的个人长期记忆。已确认的新方向是以 Workspace 为唯一长期记忆归属，项目背景进入 Project Overview（待实现）\[I1\]。

## 2. 目标与非目标

目标

- G1 用户可用自然语言调整「记什么、何时忘」，并看得见改了哪条规则。
- G2 用户明确要求记住的内容即时生效；模型推断的记忆保持批量产出。
- G3 记忆内容、记忆行为、运行设置三者分开定义、分开修改。
- G4 记忆组件保持薄：负责提供、触发、调用、版本与失效；判断交给模型。
- G5 以 Workspace 为唯一长期记忆，项目背景进入 Project Overview。
- G6 不削弱现有来源、授权、版本与用户保护机制。

非目标（第一版）

- 向量或图检索，可替换的检索策略。
- Workspace 统一配置第三方 Skill、MCP、Plugin（第二期）。
- 经验与 Skill 的自动孵化。
- 新的访问控制模型。
- 内置多 Agent 编排。

## 5. 设计原则

1. 行为描述管「如何判断」，程序管「何时执行、是否执行成功」\[I2\]。
2. 记忆内容与记忆行为分开；修改行为必须有回执 \[I2\]\[A\]。
3. 硬约束留在原生层，不可被行为定义覆盖 \[I1\]\[E13\]\[A\]。
4. 以底层返回的实际结果为准；保存失败不得说「已记住」\[I2\]。
5. 召回内容作为带标注的历史进入模型，不作为系统指令 \[E13\]\[A\]。
6. 对用户收敛概念，内部状态不变 \[A\]。

## 6. 方案概述

三层结构

1. 底层状态层（已有）：知识版本、来源状态、停用抑制、授权、Run 证明。负责失效、溯源、「忘记后下一轮不再使用」\[I1\]。
2. 记忆组件（新增，保持薄）：任务开始时提供适合使用的记忆；在触发点发起整理；让 Agent 按当前记忆行为调用底层操作；管理行为版本、更新与失效 \[I2\]。
3. 行为定义与运行设置（新增）：行为定义是一份内置、可编辑的记忆行为描述（形态为 Prompt 还是 Skill 待定）；运行设置是少量明确开关，如整理开关与频率（每天、每周、手动）\[I2\]\[A\]。

责任划分 \[I2\]

| 用户要求 | 负责方 |
| --- | --- |
| 只记稳定、跨任务有价值的信息 | 行为定义，由模型判断 |
| 合并重复，保留不同适用条件 | Agent 按行为定义提出操作 |
| 每天凌晨整理 | Harness 调度，触发后调用记忆行为 |
| 忘记后下一轮停止使用 | 记忆组件与底层状态共同保证 |
| 保存失败不能说已记住 | 底层返回实际结果，Agent 据此反馈 |

触发点 \[E6\]\[E7\]\[A\]

- 运行前注入：提供常驻快照与导航。
- 每轮结束后：是否捕获候选，待定。
- 定时整理：由 Harness 调度。
- 显式工具调用：用户要求时即时执行。

## 8. 记忆组件边界

负责：提供记忆快照；在触发点发起整理；让 Agent 按当前行为调用底层操作；处理行为版本、更新与失效 \[I2\]。

不负责：判断值不值得记、如何合并（交给模型）；另建独立推理系统（复用同一个 Agent 执行能力）；自行调度（由 Harness 调度）\[I2\]。

## 9. 验收标准（P0）

- 对话中说「记住我喜欢简短汇报」，下一轮即可生效，并出现落点回执。
- 修改行为后，行为页显示被改的规则和版本，可恢复默认。
- 试图通过行为定义把模型候选标为「用户确认」，被原生层拒绝。
- 保存失败时 Agent 不声称已记住。
- 停用某条记忆后，下一轮不再使用，同来源候选不会重新出现（现有能力回归）。
- 只读模式拒绝记忆写入；先审阅模式需确认。
- 迁移后无记忆丢失；失败时有明确提示。

## 10. 成功指标（目标值待定）

- 显式「记住」到下一轮可用的延迟。
- 落点回执覆盖率。
- 用户对记忆的纠正率与停用率。
- 行为修改后的回滚率。
- 常驻快照平均字符数与被引用比例。

## 11. 风险与待决问题

风险

| 风险 | 应对 |
| --- | --- |
| 行为定义被用来绕过保护 | M-02 硬约束清单 |
| 客户项目内容被判为通用，出现在其他项目会话 | M-16 来源标注与一键限定 \[A\] |
| 记忆越积越碎 | M-12 容量与合并 |
| 概念过多，用户看不懂 | M-11 状态收敛 |
| 迁移破坏已有记忆 | M-07 备份与失败指引 |
| 外部资料可信度有限 | 见第 13 节说明 |

待决问题

1. 行为定义最终用 Prompt 还是 Skill \[I1\]。
2. 运行时触发点集合；每轮后是否捕获候选 \[I1\]。
3. 行为修改何时生效：立即、下一轮、下一次整理 \[I1\]。
4. Agent 可以调整行为的哪些部分 \[I1\]。
5. 显式「记住」是否标为用户确认。
6. 跨 scope 联合沉淀能否做成单事务 \[I1\]。
7. 现有 Project Memory 如何迁移 \[I1 未覆盖\]。
8. L0 导航目前以什么角色进入模型（系统指令还是历史）。
9. 「项目结束后别再带入」是否映射到现有归档语义 \[I1\]\[A\]。

## 12. 阶段安排（不含日期）
