# flomo 帮助中心结构与文章模式调研

> 调研日期：2026-08-21
> 来源范围：仅使用 flomo 官方帮助中心及其链接的 flomo 官方页面。本文关注信息架构和写作方法，不复制 flomo 的产品概念、原文或品牌语气。

## 结论摘要

flomo 101 的核心不是“功能说明书”，而是把三类内容放进同一条学习路径：**功能怎么用、真实场景如何做、为什么这样做**。官方对帮助中心的定位也是“不仅解决工具如何使用，还希望帮助用户改变使用工具的思维方式”：[关于 flomo 101](https://help.flomoapp.com/about-101.html)。

其最值得借鉴的机制有六项：

1. 一级导航按用户目标和能力阶段组织，而不是按客户端或团队组织架构分类。
2. 用“快速上手”把功能说明与使用技巧并排，主动连接“怎么做”和“为什么做”。
3. FAQ 和操作页答案优先，限制、权限和外部平台约束不藏在附录里。
4. 截图紧跟动作或结果，正文末尾用上一篇/下一篇维持顺序阅读。
5. 首页同时说明擅长和不擅长什么，把产品边界也当作帮助与信任内容。
6. 在导航层直接标出 PRO / MAX，减少用户读完文章才发现权限不足的成本。

## 1. 当前信息架构

### 1.1 当前主侧栏：10 个一级栏目

根据当前[帮助中心首页](https://help.flomoapp.com/)的可见侧栏，一级栏目为：

| 一级栏目 | 主要二级内容 | 用户要完成的任务 |
| --- | --- | --- |
| Hi，共建者 | 产品首页、常见问题、快速上手 | 认识产品、判断是否适合、开始使用 |
| 快速记录 | 客户端下载、快速记录、微信输入、语音输入 | 找到最低摩擦的记录入口 |
| 更好回顾 | 多级标签、每日回顾、随机漫步、认知地图、统计、搜索、引用、历史版本 | 整理、找回、连接和回顾已有内容 |
| flomo AI | Agent、点数、相关笔记、AI 洞察、记忆档案、MCP | 理解并使用 AI 能力及其权益边界 |
| 账号及会员 | 会员、账号、存储与导出、导入、密码锁、小组件、奖励、取消续费 | 管理账号、数据、权益和付款 |
| API / 扩展 | API & URL Scheme、扩展中心 | 连接外部工具或选择现成扩展 |
| 使用指南 | 常见用法、用户故事、布道师 | 按真实场景组合多个功能 |
| 笔记方法 | 方法目录、书籍、记录/卡片/标签/连接/回顾/输出等方法文章 | 理解长期使用方法和产品理念 |
| 服务协议 | 隐私政策、用户协议 | 确认数据与契约边界 |
| 关于我们 | 联系、鸣谢、帮助中心说明、版本更新、团队、年度信件 | 获取支持并建立对团队的信任 |

这是一套“开始记录 → 更好回顾 → 学会方法 → 处理账号与信任问题”的混合架构。平台差异没有成为一级目录，而是下沉到具体任务内；例如标签修改在同一篇文章内再分 Web 端和手机端：[多级标签](https://help.flomoapp.com/basic/tag.html)。

### 1.2 二级与三级结构：浅目录为主

多数栏目采用“一级栏目 → 文章”的两层结构，只在存在稳定集合时增加第三层：

- “flomo AI → flomo Agent → Agent 点数与扩展包”；
- “使用指南 → 常见用法 → 捕捉灵感 / 读书笔记 / 积累素材 / 反思日记”；
- 在文章正文内，再用 H2 表示任务、用 H3 表示平台或子场景，例如“修改/删除标签 → Web 端 / 手机端”。

以上层级可在[首页侧栏](https://help.flomoapp.com/)和[多级标签](https://help.flomoapp.com/basic/tag.html)核验。其好处是用户不需要理解很深的目录，复杂度由文章内部标题承担。

### 1.3 主导航与全量索引不是同一套结构

[SUMMARY 全量索引](https://help.flomoapp.com/SUMMARY.html)还保留“基础功能、进阶用法、思维方式、会员相关、社群共建、隐私与协议、关于我们”等偏编辑史与内容库视角的分类，并展开大量扩展、方法子文和用户故事。它与当前主侧栏在文章归类和条目数量上并不完全一致。

因此，分析或迁移时应区分：

- **主侧栏**：当前用户的主要找路界面，应作为信息架构判断依据；
- **SUMMARY**：全量内容地图，可用于发现长尾内容和历史关系，但不宜直接照搬成用户导航。

## 2. 主要用户任务路径

### 2.1 新用户：从定位到第一次成功

路径是“首页 → 常见问题 / 快速上手 → 某个核心能力页”。首页顶部直接提供快速上手、常见问题、在线反馈和方法内容入口，同时在正文解释产品特点与不擅长的工作：[首页](https://help.flomoapp.com/)。[快速上手](https://help.flomoapp.com/how-to-use.html)再用“功能说明 / 使用技巧”对照表，把每项能力链接到功能页，并在有对应方法时配对方法文章。

这一入口不是完整的新手教程，而更像“能力地图”。它适合功能少、心智明确的产品；功能复杂时，需要另加一条有明确完成状态的最短上手流程。

### 2.2 核心任务：记录后自然进入整理与回顾

主侧栏用“快速记录”和“更好回顾”形成明显的使用顺序。单个功能页再把操作连接到方法：例如[微信输入](https://help.flomoapp.com/basic/wechat-input.html)在说明微信限制后，链接“为何收藏无用”；[多级标签](https://help.flomoapp.com/basic/tag.html)在多级标签示例后链接“用标签，让结构生长”。

这让用户既可以沿导航按产品生命周期阅读，也可以从搜索进入一篇文章后再走向相关方法。

### 2.3 遇到问题：问题标题 → 直接答案 → 深入页面

[常见问题](https://help.flomoapp.com/faq.html)直接把用户问题写成 H2，例如平台支持、数据隐私、买断、导出、导入、离线等。短答案在前，再补原因、边界和深链。例如“可以买断么”先回答“不能”，随后解释云服务成本并链接会员计划；隐私问题先给结论，再链接隐私政策。

### 2.4 从功能到实践：场景指南串联多个能力

[如何做读书笔记](https://help.flomoapp.com/community/tips/reading.html)先列用户困境，再按“原则 → 不同渠道记录 → 整理与连接 → 回顾”组织，并引用真实贡献者做法。它不是按钮教程，而是沿任务过程把记录、标签、连接和回顾组合起来。

### 2.5 技术用户与非技术用户分流

[API & URL Scheme](https://help.flomoapp.com/advance/api.html)先写会员权限和技能门槛；对没有开发技能的用户，直接给“扩展中心”替代入口；对开发者再提供路径、参数表和示例。它把受众分流放在技术细节之前。

## 3. 文章标题与内容模板

### 3.1 标题模式

flomo 没有让所有标题套同一句式，而是按内容类型选择：

| 类型 | 标题句式 | 示例与来源 |
| --- | --- | --- |
| 功能对象 | 短名词，说明页面对象 | “多级标签”“存储与导出”“微信输入”，见[主侧栏](https://help.flomoapp.com/) |
| 场景任务 | “如何 + 用户目标” | “如何做读书笔记”“如何捕捉灵感”，见[使用指南](https://help.flomoapp.com/community/tips/reading.html) |
| 方法解释 | “为何 / 如何 + 原理问题” | “为何收藏无用”“如何规划标签”，见[笔记方法目录](https://help.flomoapp.com/thinking/start.html) |
| FAQ | 用户会直接搜索的完整问题 | “flomo 支持离线输入么？”等，见[常见问题](https://help.flomoapp.com/faq.html) |
| 决策页 | 购买或选择对象 | “会员介绍”，正文再用“怎么选”，见[会员介绍](https://help.flomoapp.com/membership/pro.html) |

标题前 emoji 是导航扫描标记，不承担分类含义；检索可理解性仍来自标题文字本身。

### 3.2 功能/操作页模板

从[微信输入](https://help.flomoapp.com/basic/wechat-input.html)、[多级标签](https://help.flomoapp.com/basic/tag.html)、[存储与导出](https://help.flomoapp.com/basic/storage.html)可以归纳出：

1. **一句话能力与收益**：先回答它能解决什么问题。
2. **支持范围或前置条件**：内容类型、权限、平台或容量规则。
3. **按用户任务拆 H2**：新建、绑定、修改、导出等，不按内部模块拆。
4. **短步骤 + 就地截图**：步骤或结果出现后立即配图。
5. **限制和后果就地写**：暂不支持、删除影响、会员到期行为、外部平台约束。
6. **替代方案或方法链接**：有门槛时分流，有理念时连接方法页。
7. **上一篇 / 下一篇**：文章底部维持顺序阅读。

不是每篇都机械包含七项。例如规则型的“存储与导出”以条件和后果为主，技术参考页则用参数表替代操作截图。

### 3.3 FAQ / 决策页模板

可归纳为：**问题标题 → 首句结论 → 原因 → 当前边界/例外 → 下一步链接**。[常见问题](https://help.flomoapp.com/faq.html)反复使用这一模式；[会员介绍](https://help.flomoapp.com/membership/pro.html)则增加“商业原则 → 权益对照表 → 怎么选 → 优惠/升级/退款 FAQ”，帮助用户完成付费决策。

### 3.4 场景/方法页模板

场景页常用：**真实困境 → 可执行原则 → 沿实际过程展开 → 用户案例与结果 → 相关功能**。[如何做读书笔记](https://help.flomoapp.com/community/tips/reading.html)用贡献者署名区分不同做法，截图作为实践证据。

方法页则更接近短篇论证：**问题或冲突开场 → 原因/比喻/案例 → 方法框架 → 一句主张收束**。帮助中心明确把“思维方式”视为基础功能之外的独立内容目标：[关于 flomo 101](https://help.flomoapp.com/about-101.html)。

### 3.5 大功能 / 新能力页模板

对于需要重新建立用户心智的能力，页面比普通功能说明更完整，常见结构是：**能力定义 → 为什么做 → 最低门槛入口 → 按场景说明能做什么 → 机制与玩法 → 明确不做什么 → 与替代方案的差异 → FAQ**。例如 [flomo Agent](https://help.flomoapp.com/ai/agent.html)同时承担定位、采用、边界和付费决策前教育，不宜压缩成按钮步骤清单。

## 4. 入口、交叉链接与阅读连续性

| 连接机制 | 作用 | 第一方证据 |
| --- | --- | --- |
| 首页快捷入口 | 让新用户直接进入上手、FAQ、反馈、方法 | [首页](https://help.flomoapp.com/) |
| 固定侧栏 | 每篇文章都保留完整栏目入口，支持跳转到相邻能力域 | [首页侧栏](https://help.flomoapp.com/) |
| 功能/技巧对照表 | 同时提供“怎么做”和“为什么做” | [快速上手](https://help.flomoapp.com/how-to-use.html) |
| 正文语境深链 | 在用户刚遇到限制、门槛或方法问题时给下一步 | [微信输入](https://help.flomoapp.com/basic/wechat-input.html)、[API & URL Scheme](https://help.flomoapp.com/advance/api.html) |
| FAQ 深链 | 简答后链接完整指南、会员计划或隐私政策 | [常见问题](https://help.flomoapp.com/faq.html) |
| 上一篇 / 下一篇 | 形成按侧栏顺序连续阅读的路径 | [多级标签](https://help.flomoapp.com/basic/tag.html)、[存储与导出](https://help.flomoapp.com/basic/storage.html) |
| 联系入口 | 在数据量大、付款或故障场景就地链接客服 | [存储与导出](https://help.flomoapp.com/basic/storage.html)、[会员介绍](https://help.flomoapp.com/membership/pro.html) |

这些链接不是统一堆在文末的“相关文章”，而是在决策点出现。其编辑规则可表述为：只有当链接能回答用户当下的下一问时才添加。

## 5. 结构优势

1. **贴合产品核心循环。** “记录—回顾”直接成为一级导航，用户无需知道内部功能归属。[首页](https://help.flomoapp.com/)
2. **兼顾检索与学习。** FAQ 和功能页适合搜索直达，方法与场景页适合连续阅读；交叉链接把两者连接起来。
3. **产品取舍透明。** 首页公开“不擅长什么”，功能页公开限制和原因，会员页公开权益、选择建议和退款规则：[首页](https://help.flomoapp.com/)、[会员介绍](https://help.flomoapp.com/membership/pro.html)。
4. **浅层级但不扁平。** 主目录保持两层，复杂主题由文章 H2/H3 和少量集合页承载。
5. **内容类型各司其职。** 操作页简短、场景页过程化、方法页可论证、法律页保持正式；统一的是产品原则，不是同一个模板。
6. **视觉贴近证据点。** 截图用于证明位置、动作或结果，而不是做装饰图库；提示块主要承担风险、权限和技巧。

## 6. 借鉴边界与风险

1. **不要直接复制 flomo 的栏目词。** “快速记录—更好回顾—笔记方法”源自卡片笔记的核心循环，其他产品应先确认自己的用户任务链。
2. **不要把 SUMMARY 当当前导航模板。** 它是更完整的内容索引，包含历史分类和大量长尾项；若照搬，会把信息库结构暴露给用户。
3. **功能复杂时，快速上手表格不够。** flomo 的快速上手主要是能力地图，不是带明确完成状态的端到端教程；复杂产品应另外设计“10 分钟完成第一个任务”。
4. **方法内容必须和产品能力相互证明。** flomo 的方法论与“记录、连接、回顾”高度一致；缺少自身原则时，不应仿写励志式方法文章。
5. **真实案例不可伪造。** 场景页的可信度来自署名实践和具体结果；没有可核验用户素材时，应用明确标注的演示案例替代。
6. **emoji 只是扫描辅助。** 不应牺牲标题的搜索词和无障碍可理解性。
7. **旧内容的表现瑕疵不应迁移。** 抽样页中存在空泛 alt、旧图床、较长段落和个别标题层级不一致；新文档应统一图片 alt、托管位置和标题规范，例如[多级标签](https://help.flomoapp.com/basic/tag.html)同时出现描述性与非描述性图片文本。
8. **价格、额度和平台状态需要更新机制。** flomo 会在正文中写具体额度和权益，并提示以产品内展示为准；借鉴这种透明度时，也必须指定内容所有者和复核频率：[会员介绍](https://help.flomoapp.com/membership/pro.html)。
9. **导航和目录应有单一权威来源。** flomo 当前侧栏与 SUMMARY 的差异说明，多套手工目录会产生信息漂移；写作计划应规定哪份清单生成导航、索引和前后篇关系。

## 7. 可直接转化为写作计划检查项

- 每个一级栏目是否对应一个用户目标，而不是内部对象列表？
- 新用户是否有一条“定位 → 第一次成功 → 下一步”的短路径？
- 每个复杂能力是否同时有功能说明和至少一个真实场景入口？
- FAQ 标题是否使用用户会搜索的完整问题，第一句是否直接回答？
- 每篇操作文是否写清权限、平台、作用域、限制、失败后果和替代路径？
- 截图是否紧跟它要证明的步骤或结果，并提供可理解的 alt？
- 交叉链接是否出现在用户产生下一问的决策点，而不是机械堆在文末？
- 方法建议是否能链接回已实现的功能，功能页是否能链接到采用它的理由？
- 付费、数据、删除和第三方服务边界是否进入正文，而不是藏在协议或客服回答里？
- 是否区分当前导航、全量索引与历史内容，避免三者互相漂移？
