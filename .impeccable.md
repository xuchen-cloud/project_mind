## Design Context

### Users
Primary users are project owners, product managers, business analysts, solution managers, and cross-functional coordinators handling complex, document-heavy initiatives. They use the product during meetings, follow-up reviews, and day-to-day project coordination to capture fragmented information, turn discussions into decisions, and maintain a reliable view of current project status.

### Brand Personality
Calm, rigorous, decisive. The interface should feel trustworthy and structured rather than playful or consumer-like. It should reduce hesitation, make progress visible, and convey that the system is a serious local workspace for advancing real projects.

### Aesthetic Direction
Editorial workstation rather than generic dashboard. Use a warm light theme with restrained contrast, ink-like typography, and clear sectional hierarchy. Emphasize project state, decision records, and next actions. Avoid neon gradients, glassmorphism, generic SaaS cards, or overly dense enterprise styling.

### Design Principles
1. State before detail: the first screen should explain the project's current state before exposing raw records.
2. Fast capture, deliberate structure: QuickNote entry must feel immediate, while Records and Todos should read as more durable outputs.
3. Layered information: QuickNotes, Records, Todos, and Files need clearly distinct visual treatments.
4. Calm density: support information-rich workflows without making the interface visually noisy.
5. Local confidence: file actions, timestamps, and source context should feel dependable and explicit.
6. Short-lived inline expansion: inline-expanded content should dismiss itself when focus leaves it; if an object supports pinning, pinning overrides auto-dismiss until the user closes it explicitly.
