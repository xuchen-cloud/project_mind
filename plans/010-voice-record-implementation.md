## 1. 执行原则和完成标准

1. 按里程碑增量开发，但不能把“仅麦克风”“仅 macOS”“仅云端”当作完整功能交付。
2. 每个任务先写行为测试，再实现；OS 原生音频通过适配器隔离，并提供真实设备测试证据。
3. 持久化是最高优先级。AI 请求、前端页面、窗口卸载和网络状态不得拥有录音生命周期。
4. 原始双轨完整保存，Transcript 保持只读；模型输出和人工正文分别管理。
5. 已确认的产品规则直接实施；本文新增的工程默认值均明确标为“建议/待测”，允许凭测试结果调整。
6. 功能成功必须可观察：状态、累计保存时长、缺失区间、补转写进度和失败原因均可查询。
7. 收尾必须通过仓库完整验证和 Standards / Spec 双轴 review；发布遵循 `docs/agents/publish-flow.md`。

最终 Done：需求 D-01 至 D-17（含 D-05A）全部对应测试或实机证据；两个平台完成完整录音闭环；本地模型不依赖用户安装 Python；没有未处理的数据丢失、错误覆盖或无限等待问题。

### 3.2 需要显式记录的工程默认值

- 建议模型按需下载到应用级模型缓存，Workspace 保存模型 ID/revision 引用；允许离线导入经过验证的模型包。此项是工程建议，之前尚未单独确认。
- 录音中或暂停时切换 Workspace，建议复用“结束并保存 / 取消”屏障。
- 崩溃恢复后的未结束会话建议恢复为暂停，明确展示中断区间，不自动开麦。
- 结束采集不等待无限期网络请求：先持久化待补转写/最终纪要任务；未完成处理显示“待处理”。
- 15 分钟计时指 Recording 状态下实际采集时长，包含普通短静音，不是 VAD 语音秒数；网络重连但本地仍录音时继续累计。
- 录音中的 Record 不允许移动归属或删除；先引导结束。结束后移动资产与索引应保持一致。
- 普通 Record 导出能力保留；Voice Record 原始音频打包导出不在已确认范围。导出正文不得偷偷把 AI 快照变为用户正文。

这些边界先按建议落入实现任务说明，若与已有代码行为冲突，给出具体场景后再决策。

## 4. 数据设计与不变量

### 4.1 数据表建议

不新建与 Record 平行的会议容器。通过关联表绑定现有 `notes` / `workspace_notes`；避免同一数字 ID 在两个表间发生碰撞。

| 表（建议名） | 关键字段 | 约束 |
| --- | --- | --- |
| `voice_records` | id、project_note_id、workspace_note_id、created_at | 两个目标外键恰好一个非空；排除 QuickNote；各自唯一 |
| `speech_profiles` | kind、model_id、revision、endpoint、secret_ref、config | 云端与本地字段按 kind 校验；本地不要求 API key |
| `voice_settings` | speech_profile_id、text_profile_id、translation_profile_id、lexicon_enabled、caption_lines | 工作区设置；文本角色复用现有 Profile |
| `recording_sessions` | id、voice_record_id、lifecycle、pause_reason、started_at、ended_at、active_ms、revision | Voice Record 首版一对一；结束不能再采集 |
| `voice_audio_chunks` | session_id、source、index、start_sample、sample_count、format、path、checksum、state | source/index 唯一；workspace 相对路径；双轨对齐 |
| `voice_timeline_events` | session_id、kind、wall_time、media_position、duration、reason | 记录暂停、恢复、设备变更、缺失区间 |
| `voice_transcript_segments` | id、session_id、audio_range、provider_segment_key、text、language、revision | 最终片段幂等；不覆盖已提交原文 |
| `voice_segment_derivatives` | segment_id、kind、source_revision、model_revision、status、text | 原文版本+处理类型唯一；迟到结果不能覆盖新结果 |
| `voice_processing_jobs` | kind、input_revision、coverage、status、attempt、next_retry_at、error | 持久 outbox；重启可恢复；唯一幂等键 |
| `voice_minutes` | session_id、version、covered_ranges、transcript_revision、content、generated_at | 每会话一个当前快照；CAS 原子替换 |
| `voice_lexicon_snapshots` | scope、source_hash、source_record_versions、model、terms | 缓存可失效；会话引用固定快照 |

会话持有模型配置快照，运行中修改设置不改变当前请求含义。标题另存 `auto/manual` 所有权或等价字段；只有显式用户改标题才标记 manual。

### 4.2 时间轴

1. 音频处理使用单调时钟和 sample counter；显示标题使用录音开始的墙上时间。
2. 统一媒体时间轴对齐两路音频，保留暂停区间映射；系统时钟校正不得改变字幕顺序。
3. 原始来源缺少音频块时记录 gap，不以静默补零掩盖设备故障。编码所需补零必须有缺失标记。
4. VAD 坐标、ASR 坐标、原始文件坐标、UI seek 坐标通过显式转换处理。
5. 最终 Transcript 以稳定 segment ID 标识，不能靠显示序号或返回先后做去重。
6. 云端补转写可能晚于后续实时字幕完成：分别维护音频覆盖区间和转写版本，不能只记录“最大 segment ID”。

### 4.3 文件保存

建议把录音放入 Workspace 内专用隐藏资产目录，以不可变 voice ID/session ID 命名。数据库使用现有 `workspace:` 路径规范；Project 归属与路径搬迁必须与现有资产约定一起验证。

写入流程：写活动文件 → 周期 flush → 完成编码封装 → 原子 rename → 事务更新 chunk 清单。活动文件可恢复性由选定容器验证；不要假设任意压缩格式被强杀后都可播放。

双原始音轨必须保存。混音可以作为可重建缓存，不强制长期保存第三份完整数据。建立空间估算：例如 16 kHz/16-bit 单声道 PCM 约 115 MB/小时/轨，双轨约 230 MB/小时；实际采样率和编码由 VR-02 实测决定。

### 4.4 数据库迁移

当前 schema version 为 21，新的迁移号在实施时重新分配。迁移先备份、事务内创建扩展结构，既有 Record 保持普通类型；不复用 `workspace_notes.note_kind` 破坏 QuickNote 分类。

覆盖全新 Workspace、v21 Workspace、旧版本升级链、重复打开、迁移失败回滚。不要通过卸载或自动降级数据库来回滚版本。

## 5. 运行时设计

### 5.1 所有权

- Rust 全局 Session Manager 持有唯一录音租约；WorkspaceRuntime 持有其数据访问资源。
- 采集线程只写有界队列，不能等待模型、网络、SQLite 长事务或 WebView。
- 文件 writer、VAD、ASR 和 AI 分别消费适合自己的队列；背压先丢弃临时 UI 更新，绝不静默丢弃原始录音。
- Writer 来不及持久化时进入可见暂停/错误，而不是无限增大内存。
- 本地模型推理放在专门 worker，限制线程数量；长任务不得阻塞 Tauri 命令线程。
- 浮窗和主窗口都是订阅者；窗口重建通过 snapshot 恢复，不重启录音。

### 5.2 生命周期与健康状态分离

持久生命周期建议为 `preparing / recording / paused / ending / ended`；ASR 单独为 `connecting / ready / reconnecting / failed / catching_up`，AI 各自有状态。这样“断网但本地继续录音”可被准确表达。

| 操作 | 前提 | 后端动作 | 可观察结果 |
| --- | --- | --- | --- |
| 开始 | 无未结束会话；双路就绪；ASR 可用 | 原子占用租约、检查存储、创建 Record/session、启动采集 | 返回唯一 session ID，重复点击不重复创建 |
| 暂停 | recording | 截止到确定音频位置、flush、结束当前识别段 | 双路停止采集，浮窗仍存在 |
| 继续 | paused 且双路重新检查通过 | 新 epoch/分片、重新连接识别、恢复计时 | 同一个 session ID |
| 结束 | recording 或 paused | 停采集、flush 尾段、保存待处理任务、释放设备租约 | ended；后续只能处理已有音频 |
| 网络故障 | 正在云端识别 | 本地录音继续，登记未转写区间并重连 | 同时显示录音中/重连中 |
| 设备/磁盘故障 | recording | 暂停并保存故障点 | 有明确原因，不自动继续 |
| 崩溃恢复 | 持久会话未结束 | 修复可恢复文件、登记 gap、还原暂停状态 | 不自动采集 |

所有改变状态的命令携带 request ID 和预期 revision；快速双击、多个窗口同时操作和迟到回调保持幂等。

### 5.3 IPC 与事件建议

命令：`voice_settings_get/upsert`、`voice_profile_test`、`voice_devices_probe`、`voice_start/pause/resume/end`、`voice_snapshot_get`、`voice_segments_list`、`voice_minutes_generate`、`voice_playback_manifest_get`、`voice_recovery_retry`、模型包下载/导入/状态命令。

事件：session 状态、音量摘要、临时转写、最终片段、派生文本、纪要、模型下载进度。每个事件有 Workspace ID、session ID、revision/sequence；缺事件时重新查询快照。不要通过事件总线逐帧广播 PCM，也不要每个字幕 token 失效整个 Workspace 查询缓存。

| 第 14 分钟手动，第 15 分钟自动 | 自动节奏保留，同一时刻无重复任务 | 16 |
| 第 23 分钟结束 | 尾段与最后 8 分钟进入最终累计纪要 | 16 |
| 旧 gap 晚于纪要补齐 | 纪要修复，不永久跳过旧内容 | 10、16 |
| 用户手动改标题时 AI 返回 | 保留用户标题，自动权限不再恢复 | 16 |
| 复制纪要后下一版生成 | 正文保持原样，新纪要单独替换 | 16 |
| 故障注入强杀各保存阶段 | 有效分片保留，中断范围明确 | 07 |

| 旧普通 Record/QuickNote | 编辑保存、AI、搜索、导出无回归 | 03、13、18 |

## 9. 测试组织与执行命令

### 9.1 分层测试

- 纯逻辑：状态机、音频时钟映射、分段、去重、翻译启用边界、覆盖区间、纪要调度和标题所有权。
- 数据层：迁移、唯一约束、事务回滚、CAS、outbox、asset tombstone。
- 适配器：录制过的脱敏 WS fixture、ONNX 固定音频 golden、native capture mock。
- 前端：React Testing Library 通过用户操作验证设置、浮窗控制、字幕、正文复制和详情。
- 故障集成：注入磁盘写失败、网络断开、进程退出、事件丢失、乱序和取消。
- 平台实机：真实权限、音频来源、耳机/扬声器、蓝牙/USB、DPI、多显示器和打包后加载。

### 9.3 建议观测指标

记录 capture callback 间隔、writer 队列深度、双轨漂移、持久化落后时长、ASR final 延迟、local RTF、翻译延迟、backlog、纪要覆盖区间、CPU/RSS 和每小时文件体积。日志默认不包含密钥、原始录音内容或完整 Transcript。

本地模型建议要求目标硬件持续 RTF < 1，并预留余量；静音判句后字幕延迟、云端延迟的具体阈值由 VR-01 确定。不要把模型卡推理耗时直接当端到端字幕 SLA。

## 10. 关键风险与回滚

1. 原生系统声音能力：用 VR-01 提前证明；失败不能挪到 UI 完成后才发现。
2. AEC：保存双轨只能保留依据，去回声需要算法与时钟对齐；必须单列实机验证。
3. ONNX 包兼容：模型/Tokenizer/runtime 一起版本化；保留上一可用模型包。
4. 持久化：数据库迁移有备份，原始录音不随模型更新删除；损坏派生结果可重算。
5. 任务拥堵：音频与 AI 隔离，低优先级任务可延期；实时队列必须有上限。
6. 长会议上下文：词库有预算，纪要分块增量，gap 修复有 revision，不能无限拼接。
7. 发布回滚：可暂时关闭新建 Voice Record 入口，已保存录音仍可读取；数据库向下兼容未验证时不要让旧版本打开升级后的 Workspace。

## 11. 推荐正式 Issue 拆法与执行入口

创建一个 Voice Record 父 Issue，正文链接需求决策与本文；VR-01 至 VR-18 分拆为子 Issue 或小批可审查 PR。父 Issue 只有在 M5 完整验收后关闭，不能因某个平台先完成而关闭。

每个子 Issue 使用如下内容：

1. 用户可观察的目标与对应 D 条款。
2. 前置 VR/Issue、已验证的技术事实与仍需完成的实验。
3. 本文任务步骤与实际代码落点。
4. 测试 seam、fixture、故障场景与 Done 条件。
5. 明确不属于该子任务的后续依赖。
6. 实施后填写测试结果、平台限制、PR 与提交。

开始执行时首先读取本计划、需求决策、领域文档与发布规则，检查现有未提交文档归属，建立实现分支；先完成 VR-01/02，再推进 M1。现有动效 plans/001–009 不属于本功能前置依赖，也不修改其状态。
